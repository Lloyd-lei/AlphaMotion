# T0 结果：七变体真实数据跑通，有真实学习信号，四个新问题

**结论先说**：代码跑通了，**有真实的学习信号（不是loss下降的假象，我用非学习基线验证过）**，七个变体已经分出高低。但T0同时暴露了四个此前看不到的问题，其中**两个会直接影响T1结论的有效性**。

规模：5,000帧真实BONES-SEED（SOMA-78 → G1-29），7变体 × 300步，batch 256。零失败。

---

## 1. 有学习信号吗？有，而且是真的

单看loss下降说明不了什么——恒等映射也会让loss降。**关键是跟不学习的基线比。**

下面全部在**模型必须自己推断**的关节（未被约束的那约50%）上，按 `trainer.evaluate()` 同样的方式聚合20个batch（n=110,187个关节样本），**与§2的变体表用同一套mask、同一套聚合**，所以两处数字可直接对照：

| 预测方式 | 平均误差 | 中位 |
|---|---|---|
| **模型（AE，300步）** | **145.7 mm** | **91.1 mm** |
| 预测rest pose | 1,738 mm | — |
| 预测batch平均姿态 | 2,155 mm | — |
| 预测原点 | 2,255 mm | — |

**比最强的平凡基线好11.9倍。** 旋转同样（n=132,037，自由关节）：

| | 平均测地误差 |
|---|---|
| **模型** | **65.7°** |
| 预测单位旋转 | 95.8° |

被约束的关节误差恰好 **0.0 mm** —— RePaint式硬替换按设计工作。

> **订正记录**：本节初版写的是 139mm / 87mm / 37.6°，那是**单个batch**、且旋转用的是**全部关节**的mask（含被约束的、误差近0的那一半），与§2变体表的自由关节口径不一致——所以旋转看起来比表里的65.7°好很多，实际是口径不同。现已统一为20-batch聚合 + 自由关节mask，与§2逐行可比。同时把"约1.5个epoch"改正为**15.4个epoch**（300×256/5,000）——这个错误更要紧，见下。

### 15.4个epoch，不是1.5个——这改变了结论的解读

$$\text{epochs}=\frac{300\ \text{步}\times 256}{5{,}000\ \text{帧}}=15.4$$

初版写"约1.5个epoch"少算了10倍。**这不是措辞问题**：如果是1.5个epoch，那145mm就是"极早期就有信号"的证据；而15.4个epoch意味着模型已经把这个只有5,000帧的小缓存**反复看了15遍**，所以：

1. **不能排除记忆**。5,000帧远小于可用的124M帧，15遍重复曝光下"学到泛化"和"记住训练集"无法区分——而§3.2指出**我们根本没有验证集评估**，所以现在也无从区分。
2. **11.9倍的基线优势仍然有效**，因为它衡量的是"有没有学到从源姿态到目标姿态的映射"，而rest-pose基线连训练集都拟合不了。但它**不能**推广成"泛化能力强"。
3. **T1的结论强度取决于验证集**，这条从"应该做"升级为"必须做"。

诚实的表述是：**架构和训练链路能在真实数据上学到远超平凡基线的映射；它在没见过的数据上表现如何，本轮无法回答。**

## 3. 新发现的问题

### 3.1 [严重] 量化变体码本崩溃

| | 标称码率 | **实际用到的码字** | **有效码率** |
|---|---|---|---|
| VQVAE 16bit | 16.0 bits | **8 / 65,536** | **3.0 bits (19%)** |
| RVQ stage 0 | 10.0 bits | 5 / 1,024 | 2.3 bits (23%) |
| RVQ stage 1 | 10.0 bits | 17 / 1,024 | 4.1 bits (41%) |

300步见过 300×256×8 ≈ **61万次**码字分配，用掉8个不是"训练不足"，是**崩溃**。

**这直接摧毁码率扫描的意义**：如果实际码率永远只有标称的20-40%，"12/16/20/24 bits对比"测的就不是码率，是崩溃程度。§3.3那套率失真分析（12 bits理论下界14.2mm）也就无从对照。

标准对策：码本EMA重启死码字、k-means初始化、或改用FSQ（无码本，不会崩）。**注意FSQ在表里排第三且没有崩溃问题** —— 这本身就是一条有用的证据。

### 已实施的修复（T1前）

三处改动：

1. **数据相关初始化**。原来码本是随机高斯，离encoder实际输出分布很远，最近邻分配一开始就塌到少数码字上，EMA再也救不回来。改为**用第一个batch的真实encoder输出播种全部码字**。
2. **死码字周期性重启**。EMA计数低于其"公平份额"一定比例的码字，重新播种到当前batch的真实输出上。
3. **新增累积利用率指标**。这一条修的是**度量本身**——per-step利用率有一个结构性上限：每batch只有 $256\times8=2{,}048$ 个token，所以 $V=65{,}536$ 时per-step最多只能用到 $2048/65536=3.1\%$。**这个数字无法区分健康码本和崩溃码本**，必须看累积（历史上被用过的码字总数）。

第一版修复的阈值我定错了：用了绝对阈值1.0，而 $V=65{,}536$ 时每个码字的期望计数只有 $2048/65536=0.03$，于是**几乎所有码字每步都被判定为"死"并重播种**，码本反复抖动——比修之前更糟。改为**相对于期望份额**的阈值 + 每20步才重启一次 + 单次最多重写5%码本。

**验证（合成数据探针，80步）**：

| | 修复前 | 修复后（累积） |
|---|---|---|
| RVQ stage 0 | 2 / 1,024 | **812 / 1,024** |
| RVQ stage 1 | 1 / 1,024 | **553 / 1,024** |
| VQVAE $V$=4,096 | — | 1,938 / 4,096 (47%) |
| VQVAE $V$=65,536 | — | 2,383 / 65,536 (3.6%) |

> **口径说明（重要）**：上表两列都来自**同一个合成数据探针**（随机结构化张量，80步）。**不要**把它和本节开头那组T0数字（VQVAE 8/65,536、RVQ 5+17/1,024）并列比较——**那组来自真实训练的300步评估，是不同的测量**。我一度把两者混着讲了，是错的：跨设置的数字不能相减。
>
> 合成探针只能证明"重启机制会动、码本不再锁死在个位数"。$V$=65,536那一行只到3.6%，因为探针的数据本身只有约8个真实簇——**没有那么多结构可编码**。真实数据上到底能用到多少，只有T1能回答，届时看 `usage_cumulative`。

### 3.2 [严重] 没有验证集评估

`trainer.py` 里没有任何 `val_` / `validate` / split过滤。`best.pt` 是**按训练loss**选的，`evaluate()` 也跑在训练数据上。

好消息：T0缓存**全是 `train` split**（5,000/5,000），所以**当前数字没有泄漏**——它们是训练集数字，不是被污染的验证数字。但T1必须有 `val_id` / `val_actor` / `val_topo` 三路评估，否则**七变体的排序无法支撑任何泛化结论**。

### 3.3 [已修] MPJPE被约束关节稀释了一倍

`mpjpe_mm` 对**所有**关节取平均，包括硬替换成GT、误差恒为0的那49%。所以原来报的72.7mm其实是**真实推断误差的一半**。

已改：新增 `mpjpe_free_mm` / `mpjpe_free_median_mm` / `constrained_fraction`，`rotation_free_deg` 同理。**上面表格用的都是修正后的自由关节数字。**

### 3.4 [已修] `latent_jump_l2` 硬编码为0

它一直返回常量0.0，却出现在指标表里**看起来像一次测量**。已删除并注明：它需要连续帧，单帧Round-1没有，等时序阶段再加。

**这是本项目第四次出现同一类错误**（re-gauge测代数恒等式、φ的gauge不变性、`gradient_norms` 传未加权项、现在这个）：**报告一个对被测对象不敏感的量**。

## 4. 误差分布：腿比手臂差一倍

自由关节误差最大/最小：

| 最差 | mm | | 最好 | mm |
|---|---|---|---|---|
| left_ankle_pitch | 202 | | right_shoulder_yaw | 61 |
| waist_yaw | 145 | | right_elbow | 62 |
| right_ankle_pitch | 142 | | left_elbow | 74 |
| left/right_hip_roll | 140 | | | |

**下肢系统性比上肢差**。合理解释：约束给的是踝和腕（末端），髋/膝在链中间且腿链更长，误差沿运动链累积——正是AvatarPoser那篇指出的现象。`waist_yaw` 差是另一回事：它是zero-length关节，几何anchor退化。

**twist DOF（那4个位置观测不到的）**：

| | 旋转误差 |
|---|---|
| left/right_ankle_roll | 34.4° / 32.2° |
| left/right_wrist_roll | 30.7° / 26.2° |
| 其余非roll关节 | 34.9° |

**twist并没有比其他关节更差**（26-34° vs 34.9°）。这是ΔR表示有效的**第一个正面证据**——如果只输出位置，这4个DOF根本没有可学信号；现在它们和普通关节同一水平。

## 5. loss平衡（重标定后的实测）

step 0有效（加权）梯度占比，AE：

| 项 | 占比 |
|---|---|
| bone | 44.9% |
| position | 32.3% |
| constraint | 12.2% |
| **delta_rotation** | **7.7%** |
| attention / limit / axis | 1.4 / 1.4 / 0.2% |

比重标定前（rotation 0.0%）健康得多。但 `bone` 又回到45%——因为重标定是在1024帧上测的，5000帧上分布不同。**T1前应该在T1的实际数据上再测一次**，或者干脆做在线自适应加权。

300步后各项降幅：position −97.8%、bone −99.9%、constraint −97.5%、**delta_rotation −63.0%**、limit −92.9%、axis −73.3%。旋转降得最慢，和它梯度占比最低一致。

## 6. T1前必须做的

**阻塞**：
1. **修码本崩溃**（EMA重启 / k-means初始化）——否则码率扫描无意义
2. **加验证集评估**（`val_id` / `val_actor` / `val_topo`）——否则排序不支撑泛化结论。**在15.4个epoch的重复曝光下（见§1订正），这条尤其要紧：现在完全无法区分"学到映射"与"记住5,000帧"。**

**应该做**：
3. 在T1数据规模上重测梯度平衡
4. `waist_yaw` 这类zero-length关节的anchor退化处理需要检查
5. spec §0.25那四项训练前分析仍未做，其中**GT噪声地板**决定了145.7mm这个数字距离天花板还有多远

**不阻塞**：下肢误差偏大是预期的（链更长），有了验证集再看是否需要按链深度加权。

## 0. 我上一版说错了什么

我说："人的'抬手'和G1的'抬手'方向是一样的，把人的方向串配上G1的骨长，出来就是G1的抬手，**这不是训练出来的，是几何上自动成立的**。"

**最后半句是错的。我实测了。**

在唯一有真实GT的配对（SOMA-78 → G1-29）上，按关节名建立对应，把源的骨方向拷到目标骨上、配目标骨长重建：

| 做法 | 误差 |
|---|---|
| (a) 直接拷贝方向 | **243.5 mm** |
| (b) rest-relative 旋转迁移 | **262.5 mm** |
| (c) **什么都不做**（目标rest pose） | **170.6 mm** |

**两种拷贝都比什么都不做更差。**

### 为什么

查了对应关系本身，发现问题不在方法而在**"同名不同骨"**：

| G1 的骨（parent→joint） | 我配给它的 SOMA 骨 |
|---|---|
| `left_shoulder_pitch ← waist_pitch` | `LeftArm ← LeftShoulder` |
| `left_shoulder_roll ← left_shoulder_pitch` | `LeftArm ← LeftShoulder` |
| `left_shoulder_yaw ← left_shoulder_roll` | `LeftArm ← LeftShoulder` |
| `left_knee ← left_hip_yaw` | `LeftLeg ← Hips` |

**G1的"肩pitch骨"是躯干到肩膀那一段，SOMA的`LeftArm`是上臂。** 我把上臂的方向拷到了躯干段上。

而且G1把一个物理肩关节拆成 pitch/roll/yaw **三个串联节点**，三段共同实现一次旋转。SOMA的一根上臂**没有任何单独一段与之对应**。

### 结论：一根骨对一根骨的映射不存在

**这才是"翻译"必须由网络学的原因。** 如果存在逐骨对应，那这就是查表，不需要神经网络。真实情况是：

$$\text{源的 } B_1 \text{ 根骨} \longrightarrow \text{目标的 } B_2 \text{ 根骨},\qquad \text{没有一一对应，}B_1\neq B_2$$

网络要学的是**整体姿态语义的映射**，不是逐骨的坐标变换。SAMoR的8个part token正是这个思路——**先收敛到与骨架无关的摘要，再发散到目标骨架**，中间刻意不建立逐关节对应。

## 1. 鸟扑翅膀 → 机器人；G1 学鳄鱼爬行

有了上面的负结果，这个问题的答案就清楚了，而且要**分成两件事**。

### 1.1 能做到的：拓扑无关的编码

编码器吃进 $J$ 个关节的token，输出 $K=8$ 个 part token。这个操作**对 $J$ 不敏感**（cross-attention的query数固定为8，key/value数是 $J$）。所以：

- 鸟（翅膀、两条腿、尾巴）→ 8个token ✓
- 鳄鱼（四条腿、长尾、脊柱多节）→ 8个token ✓
- G1（29个DOF轴）→ 从8个token解出29个 ✓

**这部分是纯粹的架构性质，不需要动作对应。**

### 1.2 做不到的：语义上"对"的映射

**鸟扑翅膀映射到G1，几何上一定能出一个姿势，但那个姿势对不对，没有任何东西能定义。**

- 鸟的翅膀有 3 段 + 羽毛，G1 的手臂有 7 个DOF——**没有GT告诉你翅膀的第2段该对应手臂的哪一部分**
- 鳄鱼四足着地，脊柱侧向波动；G1 双足、腰只有 3 个DOF——**"鳄鱼爬行"在G1上的正确形态是什么，这是个开放的美学/动力学问题，不是数据问题**

**所以引入动物骨架的价值不在"翻译到动物"，在别处**：

| 目的 | 有没有GT | 价值 |
|---|---|---|
| 让编码器见过非人形拓扑 | 不需要GT（自重建） | **高**：逼迫瓶颈真正拓扑无关，而不是记住人形的77根骨 |
| swap-consistency / 具身判别器有活干 | 不需要GT | **高**：只有一个具身对时这两个loss形同虚设 |
| 鸟→G1 的定量精度 | **没有** | **不可评估**，不要写进验收指标 |

**这意味着**：动物数据走**自重建路径**（鸟→鸟、鳄鱼→鳄鱼），作为正则化；跨物种映射可以在Studio里**定性地看**，但**不能作为指标**。我在round1的计划里把这条写成了"能得到的/得不到的"，现在有了上面的负结果，理由更硬了。

### 1.3 如果你真的想要"G1 学鳄鱼爬行"

那不是retargeting问题，是**风格迁移 + 物理可行性**问题，需要的是：
1. 定义"爬行"的**可度量特征**（接触序列、质心高度、步态相位），而不是逐关节位置
2. 在G1的可行域内**优化**这些特征，而不是从鳄鱼拷贝坐标

这是完全不同的技术路线（更接近 BeyondMimic / 物理RL 那一支），**不在第一阶段的翻译器范围内**。我建议明确划出去，否则会污染第一阶段的验收标准。

## 2. 骨长到底进不进神经网络

**进。我上一版说得有歧义，澄清一下。**

我说的是"**骨长不是网络要预测的输出**"，不是"骨长不进网络"。三者的区别：

| 量 | 进encoder输入? | 进decoder输入? | 是网络的输出? |
|---|---|---|---|
| 关节方向/位置 | ✓ | — | **✓ 是** |
| **骨长** | **✓ 是** | **✓ 是** | **✗ 否** |
| 拓扑、语义、限位 | ✓ | ✓ | ✗ |

**为什么必须进输入**：同一串关节角，在长腿和短腿上产生完全不同的末端位置。网络要判断"这个姿势在目标身上是否可行、末端会落在哪"，**必须知道目标的尺寸**。

**为什么不能是输出**：骨长是骨架的固有属性，是**已知常量**。让网络预测一个已知量，只会引入误差。

具体到现在的代码，这些已经在了（`bone_anchor`）：
- 归一化骨长 $L_j / H$（$H$ = 骨架高度，尺度无关）
- 父子相对骨向量方向
- 侧别通道

**所以你的理解基本正确，只差一处**：不是"骨长不进网络"，是"**骨长进网络但只作为条件，不作为待预测量**"。

## 3. SE3约束做成可选：这正是当前设计，但训练课程要改

你说"大部分时候直接转换姿势，除非我要规定某个关节必须在某点上"——**这是对的用法，而且架构已经支持**。

### 3.1 机制上它已经是可选的

约束通过 mask 表达：

```python
ctrl_mask[j] = 1   # 这个关节我要钉死
ctrl_mask[j] = 0   # 这个关节你自己决定
```

**全 0 = 纯姿势转换**（你说的"大部分时候"），**部分为 1 = 局部精修**。同一个模型、同一次前向，不需要两套权重。

### 3.2 但训练分布必须匹配你的使用分布

这里有个陷阱，而且**我们刚被它坑过**。

Codex 发现模型完全不看源姿态。根因是我修的那个GT泄漏——但**即使没有泄漏，如果训练时约束总是很稠密，模型也会退化成纯IK求解器**：

$$\rho \to 1 \ (\text{约束稠密}) \implies \text{答案被约束唯一确定，源姿态无关紧要}$$
$$\rho \to 0 \ (\text{无约束}) \implies \text{只能靠源姿态，这才是"翻译"}$$

**你说"大部分时候是 $\rho=0$"，那训练分布就必须以 $\rho=0$ 为主。**

我建议的采样比例：

| 模式 | 占比 | 对应你的用法 |
|---|---|---|
| **无约束**（$\rho=0$） | **60%** | 大部分时候：直接转换姿势 |
| 稀疏约束（1–3个关节） | 30% | 偶尔：钉死手/脚 |
| 稠密约束 | 10% | 少见：整体对齐 |

这和之前定的 2:6:2 不同——**之前那个是按"我们希望模型擅长约束控制"定的，现在按你实际的使用分布定，无约束应当占大头**。

### 3.3 一个必须加的验收项

既然 $\rho=0$ 是主用法，**验收就必须在 $\rho=0$ 下做**。当前所有报告的数字都是在有约束的条件下测的——而我们已经知道那种条件下模型可以靠IK蒙混过关。

**新增指标**：`mpjpe @ ρ=0`（完全无约束下的翻译误差）。这个数字**不能**靠约束泄漏作弊，是翻译能力的唯一诚实度量。

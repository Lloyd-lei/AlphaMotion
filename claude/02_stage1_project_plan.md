# 文件3：第一阶段项目规划

**第一阶段的定义**：做出一个可用的**单帧跨具身"翻译官"**——不依赖参数化retargeting算法，能把任意骨架的一帧姿态翻译到任意其他骨架，并精确遵守用户指定的SE3约束。

时序、文本prompt、环境感知、PD输出都不在第一阶段。

## ⚠️ 项目最高层scope（一切设计的红线）

**一次unified universal的大型预训练，泛化到所有拓扑构型。不为任何单一构型微调、不加专属的encoder / decoder / 输出头。**

**验收判据**：给一个训练时从未见过的机器人，只提供它的URDF/骨架定义，模型必须直接输出可用结果——**不新增任何参数、不训练任何东西**。

这条红线的意义：如果接入第N+1种构型需要改网络或重训，那就不是一个universal模型，只是一堆专用模型共享了一个编码器。§8.1第1条记录了一次实际发生的跑偏（我曾把"给G1加一个关节角头"写进方案），可作为反面样例。

**这条红线在实验层面对应§3的第8项验收**（零样本新机器人测试）——它比任何单一具身上的精度数字都更能说明本轮是否成功。

# 1. 为什么先做单帧

三个理由：

1. **它本身就是一个可交付的产品**——关掉时间轴，这一层直接就是一个跨机器人的**遥操作接口/姿态翻译器**，不需要等时序层做完才有用。
2. **它是后面所有东西的地基**。时间层在这一层的latent空间里工作；如果这一层的表示有缺陷（比如旋转不可观测），时间层会继承这个缺陷且无法自行修复。
3. **它可以被干净地验收**。有GT（SOMA→G1配对；以及GT更干净的剪枝拓扑）、有明确的数值指标（末端误差mm / twist角误差度）、有非学习基线可比。而生成类任务的验收要模糊得多。
   **但要诚实标注GT的性质**：SOMA→G1的GT是NVIDIA retargeter产物、不是物理真值，所以那条路径实质是蒸馏retargeter。**GT无歧义的是剪枝路径**（确定性子集选取）——核心结论应建立在它上面（spec §3.0/§6.2b）。

# 2. 里程碑

## M0：管线打通（阻塞项，无模型）

**产出**：能从磁盘读出一对 (SOMA帧, G1帧)，两侧在同一坐标系下，可视化叠加看起来是同一个姿态。

**关键交付**：
- G1 FK管线（URDF→3D位置，可微实现）
- 坐标系统一 + 四项验收单元测试（det=+1、左髋在+X、行走方向一致、**左手挥手确认是同一只手**）
- G1 CSV的root列单位/轴序实测确认
- 关节名规范化表（SOMA-78 + G1-29 共107项）

**验收标准**：随机抽20对样本，SOMA与G1骨架叠加渲染，人眼确认姿态一致且左右不反。

**这一步没做对，后面全白做，而且错误极难在训练指标上察觉。**

## M1：T0冒烟

**产出**：七个变体各跑通5k帧，loss正常下降，shape无误。

**验收标准**：每个变体的训练loss在1000 step内明显下降；forward/backward无shape错误；能存取checkpoint。

**不看效果，只看能不能跑。**

## M2：动物骨架接入

**产出**：Truebones Zoo（65物种）转成统一格式，按物种切分，功能组标签映射完成。

**验收标准**：能构造出一个batch同时包含SOMA帧、G1帧、动物帧，三者走同一个encoder不报错；`val_topo`（约10个held-out物种）可正常评估。

**这一步是`val_topo`指标的前提，也是$\mathcal L_\text{adv}$真正有意义的前提。**

## M3：T1正式实验

**产出**：七变体 × 3 seed = 21次训练，**13项指标**的完整对比表 + 两个非学习基线。

**验收标准**：
- 七个变体的排序**跨3个seed稳定**（如果不稳定，说明200k帧不够，需上调数据量或延长训练）；
- 至少有变体打得过最近邻基线（打不过说明只是在记忆，不是在泛化）；
- 能明确回答："哪个瓶颈胜出？在SE3精度维度还是跨拓扑维度胜出？"

## M4：viser验收

**产出**：可交互的可视化demo，能直观判断翻译质量。

**验收标准**：见§4。

## M5（可选）：T2定论

只在T1排序稳定后进行，1-2M帧确认结论、给最终数字。**如果T1的排序已经很清楚且差距明显，可以跳过直接进入第二阶段。**

# 3. 第一阶段结束时要能回答的问题

这是验收清单，不是KPI。每一条都应该有数据支撑的明确答案：

1. **七个瓶颈里哪个最适合做翻译官？** 在SE3精度和跨拓扑泛化两个维度上分别是谁？
2. **压缩到底有没有代价？** Direct-Token（无压缩）vs 其余六个的对比给出了什么？
3. **量化会不会造成抖动？** 指标10（帧间瓶颈跳变）在VQ/RVQ/FSQ上是否显著高于连续瓶颈？**这一条直接预测时序阶段的表现。**
4. **学习式方法有没有超过解析IK？** 如果没有，是精度不够还是泛化不够？
5. **$\varphi$（twist）通道work不work？** 特别是那4个从位置不可观测的twist DOF（双踝roll、双腕roll），单独统计的误差是多少？（v6：不是"旋转头"——旋转由**一个通用头输出的标量$\varphi$** + 构造式triad合成，见spec §1.2）
6. **跨拓扑泛化到什么程度？** 在held-out动物物种上的误差 vs 在见过的拓扑上的误差，差多少倍？
7. **$K$取多少合适？** SAMoR说8，但那是动画任务；我们的SE3控制场景呢？
8. **零样本新机器人成不成？** 取训练时完全没见过的URDF（`g1_23dof.urdf` 同家族 / Go2 跨家族），不训练不加参数直接推理，**报可行性筛查**（限位违反率、骨长守恒、axis残差、是否NaN/退化）——**不报末端误差，因为没有配对GT**（v6修订，此前与本文档§7自相矛盾）。真正的翻译精度结论来自spec §6.2b的T-c（未见剪枝拓扑，GT无歧义）。

# 4. Viser：翻译官的"chatbox"

大模型训完需要chatbox来验证，翻译官同理。数字指标会平滑掉肉眼可辨的定性差异（比如VQ系的抖动感），所以这一环不是可选项。

viser 1.0.16 已装在 ardy/kimodo/kimodo-bones。仓库里已有 `experiment/stage1/viser_compare.py`（三骨架对比浏览器）可作起点。

## 布局

| 区域 | 内容 |
|---|---|
| 左栏 | **源骨架**（SOMA-78），显示输入pose；被约束的关节高亮 |
| 中栏 | **目标骨架翻译结果**，两个下拉框：切换目标拓扑（G1-29 / SOMA-24 / 各动物物种）、切换瓶颈变体（Direct-Token/AE/.../FSQ） |
| 右栏 | **GT对照**（若有）或**误差热力图**（关节按误差着色） |
| 控制面板 | ① 帧slider ② **关节约束编辑器**（点选关节→拖gizmo→实时重新脑补） ③ 骨长滑块 ④ 实时数值面板（末端误差/旋转误差/限位违反） |

## 三个核心交互（验收靠这个，不是靠图好看）

1. **拖动一个关节 → 全身实时联动**：直接检验"稀疏约束+脑补"是否work，比任何数字都直观。
2. **同一输入切换七个变体**：定性差异（VQ系是否有抖动/卡顿感）肉眼可辨，但在平均误差上会被平滑掉。
3. **骨长滑块推到训练分布之外**：看模型是崩溃还是优雅退化。

建议实现成独立脚本 `viser_translator_demo.py`，多个变体checkpoint加载到同一进程共享测试数据。

# 5. 第一阶段与后续的接口

第一阶段交付的东西，第二阶段（时序层）要直接用：

- **零per-embodiment这条约束在第二阶段同样成立**，而且更重要：时间层工作在canonical latent空间里，如果第一阶段的解码器带per-embodiment分支，时间层每接一个新机器人也要跟着改，整套架构的universal性就全毁了。第一阶段守住这条，第二阶段才可能守住。
- **瓶颈latent $z$** 是时间层的工作对象——时间层预测 $z_{t+1}$ 而不是关节坐标，全程留在canonical空间。所以第一阶段选出的瓶颈形式**直接决定第二阶段的可行性**：如果选了量化瓶颈，时间层就是离散token自回归；如果选了连续瓶颈，就是flow matching/回归。
- **指标10（帧间瓶颈跳变）是第二阶段的先行指标**——它在第一阶段就能预测时序阶段会不会抖。
- **$\varphi$（twist）通道**在第一阶段就必须做对（见文件2的§1.2）。若第一阶段只做位置，时间层对那4个twist DOF没有可观测信号，IK后处理逐帧独立地猜，直接表现为时序抖动，而这是表示缺陷造成的，时间层的平滑loss只能掩盖不能消除。

# 7. 关于"引入动物骨架，机械狗是不是就顺带解决了"

**能得到的**：一个见过四足/鸟类/爬行类拓扑的编码器。这让"任意骨架"不再是空话，也让$\mathcal L_\text{adv}$和swap-consistency真正有活干。这是必要前提。

**还差三步**：
1. **没有四足侧的配对GT**。SOMA→G1能训是因为NVIDIA的retargeter提供了逐帧配对；狗→Go2没有，需要另外构建。
2. **动物↔机械狗的gap比人↔人形更大**：动物脊柱柔性多节、机械狗躯干刚性；四足步态相位（trot/bound/gallop）与机器人可执行步态集不重合；爪蹄与足端接触模型不同。
3. **动物动捕的物理质量通常差于人体动捕**（穿模、脚滑、骨长不守恒更常见）。SAMoR做动画对此容忍度高，机器人不行。

机器上有 `go2-convex-mpc` 环境，说明四足线确实在跑。**这条路是通的，但属于第二阶段**：先用Truebones把编码器的拓扑覆盖打开，再单独补一份Go2配对数据做四足侧验证。

**第一阶段不要把"机械狗动作生成"写进验收目标**——缺GT会导致无法验收。

**v7（第二轮）**：Codex对v6的旋转表示提出新P0，**两条都对**，v6的标量$\varphi$方案已作废：
- $\varphi$ **不gauge-invariant**——我只测了 $E$（由位置构造，必然不变），没测真正携带旋转信息的量。实测随机per-link re-gauge下 $|\varphi-\varphi'|$ **最大180.0°**。
- **joint axis根本不沿bone axis**——G1的29个revolute里 **23个**无法用"绕bone轴的标量"表示（19个PERPENDICULAR、3个oblique、1个zero-length）。`ankle_roll` 的 $|\cos|=0.000$，标量能表示它的 **0%**。

Truebones Zoo的**motion数量极少**——SAMoR原文Table 1给的是939训练/110验证motion，而BONES-SEED有142,220条。**不做过采样，动物样本会被完全淹没**，`val_topo`和$\mathcal L_\text{adv}$都会失效。

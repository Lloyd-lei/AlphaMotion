# sajio/alphamotion-soma-h2 数据集质量评审（0915）

## 数据集是什么
- 26,111 段 H2 动作 = 13,055 个动作 × 2（左右镜像），2,518 个 take，95 个演员，共 50.7 小时，30 fps。
- 来源：SOMA/BoneSeed 人体动作 → AlphaMotion 生成 H2 关节角。
- 类别：走路类最多（普通 8.3k、风格 2.4k、进阶 1.7k、特殊 1.4k），手势 2.8k，跳舞 2.1k，物体交互 1.9k。
- 每段存：43 节点关节角、根旋转、根位置（Y-up cm，地面 0）、两脚鞋底高度、模型接触标签。
- 归档里没有 SOMA 原始人体动作，看不到"人怎么做的"，只能看机器人自己。

## 组员自己的验收（README 说 91.1% 通过）
- 抽了 2,000 段做筛查：脚滑 >15 cm/s 且持续 0.1 s、穿地 >0.5 cm。
- 结果：1,535 通过（77%），447 不通过（22%），18 没法评。
- 但最终"good"有 1,871（93.5%）：**319 段筛查不通过的也标成了 good**，因为最终标签只看另一条更宽的"固定支撑漂移"规则。
- 另外 372 段（19%）是"没确认过支撑就接受"。
- 所以 91% 是宽口径；按他们自己的严口径只有 77%。

## 我的复测（随机 60 段，用他们的 43 节点骨架做 FK，鞋底 <1 cm 算踩地）
| 指标 | 结果 |
|---|---|
| 踩地时鞋底速度 p95（中位数） | 18.8 cm/s（最差 195） |
| 每次踩地漂移 p95（中位数） | 9.2 cm（最差 73） |
| 超过他们 15 cm/s 门槛的段数 | 35 / 60 |
| 超过 8 cm/s 的段数 | 50 / 60 |
| 穿地 <−0.5 cm 的段数 | 3 / 60（最差 −4.1 cm） |
| 根高单帧跳 >3 cm | 11 / 60 |
| 关节抖动 p95（中位数） | 16 °/s²（比 G1 真值 36–46 还平滑，好） |
| 接触标签全 0 的段数 | **47 / 60**（标签基本没用） |
| 根高中位数 | 102.5 cm |

组员的脚滑量法是先按"源动作慢且平"挑帧再量，把脚正在滑的帧排除掉了，所以他们的中位数 6.9 cm/s 比我的 18.8 低。

## 肉眼看（8 段视频 + 12 帧网格）
- 站得住，姿态自然，走路/瘸腿走/拄拐走/转身跳舞都像那么回事，没有深蹲、没有翻倒。
- 静帧看不出脚滑；视频里能看到脚在地上"蹭"。
- 最差的两段：dance_basic_turn（滑 195 cm/s）、injured 走路循环（171）。

## 其他问题
- 元数据里的 H2 MJCF sha 和我们本地 H2_loop.xml 不一样；他们的 43 节点骨架和训练时的 H2 描述（32 关节）也不一样，等于 H2 是零样本跑的。
- 43 节点里有 6 个闭环辅助关节本地 MJCF 没有，导出到别的仿真要先对齐。

## 结论
- **姿态可用，脚不可用。** 当 locomotion 训练/展示数据，一半以上的段脚滑超线，接触标签基本是空的。
- 数字和视频都指向同一个病：根位置透传 + 关节角没钉脚，脚在地上飘。这和我之前在 G1 上量到的一样。
- 建议：用新管线（钉脚精修 + locomotion.v1 十一门 + 视频复审）重跑，别直接发布这版；至少把 README 的 91% 改成 77% 并注明接触标签为空。

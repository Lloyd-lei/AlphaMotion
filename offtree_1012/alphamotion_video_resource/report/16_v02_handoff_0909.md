## 2. 接口怎么用

```bash
pip install -e .                       # 产品包
alphamotion download                   # 拉 v0.1 全套 + megatron
alphamotion download --models bumblebee,megatron,prime   # 拉整套 v2
```

```python
from alphamotion.engine.greenwich import Greenwich

gw = Greenwich.load(model="megatron")        # 或环境变量 ALPHAMOTION_MODEL=megatron
gw.code_shape                                 # (132, 13)：4 个位置槽 + 128 个旋转槽，32 级 FSQ

spec, dof, rest = gw.embodiment("unitree_g1_29dof")   # 必须用这个拿骨架描述，见第 3 条
p9, reach = gw.pose9(local6d, spec)           # [T,J,6] 局部旋转 -> [T,J,9] 编码器输入
codes = gw.encode(p9, spec, dof)              # [T,132,13] 整数码
rot6d, pos = gw.decode_full(codes, spec, dof) # rot6d [T,J,6] 全局；pos[:,root,0] = 根离地高（米）
rot6d, pos, con = gw.decode_full(codes, spec, dof, contact=True)   # 多一个 [T,J] 接触 logit

h_spec, h_dof, _ = gw.embodiment("human_smpl")
g1_rot6d = gw.translate(p9_human, h_spec, h_dof, spec, dof)        # 人 -> G1 一步翻译
```

`Greenwich.load()` 不传 model 时还是 `greenwich`（v0.1），服务端行为不变。

## 3. 四条纪律（踩过坑的）

1. **骨架描述跟着模型走。** v2 训练用的是 LAFAN-v3 的骨架（`assets/embodiments_v2/`，16 台，pal_talos 和 engineai_pm01 训练时剔了）。它和 v0.1 那套 rest offset 差得很大（booster_t1 差 91 cm，人体差 47 cm）。**给 v2 模型喂 v0.1 的描述 = 静默错 10–50 cm。** 用 `gw.embodiment(name)`，别用 `registry.load()`。
2. **名字嵌入跟着模型走。** v2 用 SigLIP（768 维，包里带缓存），greenwich 用 Qwen3。没见过的关节名会现场编码，要装 `alphamotion[labeling]`。
3. **码空间不通用。** v2 的码不能塞给 greenwich 解，反过来也不行（`decode` 会 assert）。Equator A/B、Atlas、4096 条片段库全是 greenwich 的码，所以时间线编辑器现在还跑 greenwich。用 v2 码重建这三样是 v0.3 的活。
4. **接触通道可选。** `encode(..., contact=None)` 和没这个通道的模型逐位一样；有接触标签器时传 `[T,J]` 的 0–1 软标签。

## 4. 更新了什么（产品包代码）

- `engine/nets/codec.py`：加接触通道（`con_emb` + `hcon`）、位置码本（`n_latent_p`）、根高头。新模块建在最后，老 C1 权重照旧逐位 strict-load。
- `engine/greenwich.py`：`MODEL_CONTRACTS` 逐模型锁架构；`Greenwich.load(model=)`；`n_slots` / `code_shape`；解码走 FSQ 网格反量化（不再写死 128 / 8 级）；`embodiment()`。
- `embodiment/semantics_map.py`：SigLIP 文本塔 + 缓存。`engine/descriptor.py`：`bundled_cache(version)`。
- `weights.py` / `config.py` / `cli.py`：四个模型的下载表、`ALPHAMOTION_MODEL`、`download --models`。
- `scripts/export_weights.py`：从研究 checkpoint `runs/L_{S,M,L}20k_0903` 导出；`scripts/verify_v2_port.py`：和研究代码逐位对齐（同输入 0 个码差，旋转 / 位置差 0.0，人→G1 翻译差 0.0；包自带 FK 有 3e-7 浮点差，164736 个码里翻 1–2 个边界码）。
- `tests/unit/test_v2_models.py`；`docs/BENCHMARK.md` 加了 600 条语料外审计表；`CHANGELOG.md`。

数字（600 条 heldout AMASS，G1 全身旋转误差）：bumblebee 8.0°、megatron 6.5°、prime 6.4°。M 到 L 只差 0.1°，所以默认推 megatron。

## 5. git 和 HF 两边怎么搞（以后改东西）

**改代码**
1. 从 `release/v0.2`（或合并后的 main）开自己的分支，改完 PR。
2. 跑 `PYTHONPATH=src pytest tests/unit`；动了 codec 或 greenwich.py 的话，在研究机上跑 `python scripts/verify_v2_port.py`，必须 PASS。
3. 别改 `MODEL_CONTRACTS` 里已发布模型的合同；新模型加新条目。

**换模型 / 加模型**
1. 研究机上：`python scripts/export_weights.py <name>`（`EXPORTS` 里加 run 路径）→ `weights_staging/<name>/`。
2. `weights.py` 的 `ARTIFACTS` / `MODELS` 加一行，`greenwich.py` 的 `MODEL_CONTRACTS` 加合同，`verify_v2_port.py` 的 `MODELS` 加一行跑一遍。
3. `HF_TOKEN=<write token> python scripts/upload_hf.py`（整包上传 `weights_staging/`，约 1.2 GB；改 commit message）。write token 找 lloyd 要，仓库属于 HF 账号 `lloydlei`（注意不是 `lloyd-lei`）。
4. `docs/BENCHMARK.md` 补审计数字，`CHANGELOG.md` 加一条，PR。

**研究仓**：分支按日期起名（`research-MMDD`），commit 按"数据 / 配方 / 判官 / 报告"分块，`.bak_*` 和 `__pycache__` 不进仓。

# R3 收尾 —— 跨具身翻译(any→any)+ dual-FSQ + twist 调查

日期:2026-08-02 · 数据:BONES-SEED 配对 SOMA↔G1(48k 对齐帧,同动作)· 指标已修正(见末尾 bug)

> 目标(用户提出):一套权重,任意骨架输入 → 任意骨架输出(human/g1 互译),用 FSQ;并用"位置一路FSQ、twist一路FSQ + FK组合"攻 twist。

---

## 一、诚实结论(有效指标下)

**跨具身翻译在这套"编码源→共享FSQ码→解码目标"的自编码框架里没有work。能work的只有自重建。**

| | 位置 | 旋转 |
|---|---|---|
| 自重建 soma→soma | ~2.5cm ✅ | ~90°(twist墙)❌ |
| 自重建 g1→g1 | ~3cm ✅ | ~13°(机器人)✅ |
| **翻译 soma→g1** | **~22cm ≈ 25cm基线,失败** | 随机 ❌ |
| **翻译 g1→soma** | **~18cm ≈ 基线,失败** | 随机 ❌ |

网络学会了"各自把各自的身体编码还原",但**没学会在身体之间翻译**——交叉方向位置贴着"什么都不做"的平均姿态基线(25cm)。

---

## 二、试过的、失败的(负结果,省得重走)

1. **any→any 4方向联合 + 单FSQ**:自重建好,翻译交叉 ~20cm(≈基线)。
2. **dual-FSQ(位置码 + 旋转码分离)**:确实解冻了旋转学习(单FSQ下 g1 旋转冻在120°,dual下降到13°)——**但主要救机器人;人体旋转仍卡~90°(twist深墙),翻译仍失败**。
3. **码对齐(让同动作的 soma/g1 编码相同)**:
   - L2 弱(w=1):对翻译零效果。
   - L2 强(w=10):**码坍缩**(align_dist→0.0001,全随机)。
   - 对比 InfoNCE(w=0.5):码没坍缩但也没聚拢(align_dist 反增),翻译仍~20cm。
4. **直接监督 soma→g1(无self-recon、连续无FSQ)**:位置卡死在25cm基线2500步没动——去掉self-recon后解码器学不到"合法g1姿态",反而更差。

---

## 三、机制判断

- **位置**:活在共享3D欧氏空间,理论上可翻译;但本框架没学出来(自重建捷径主导,交叉被牺牲;对齐机制都没能强制具身无关码)。
- **旋转**:soma→g1 全局旋转是跨骨帧约定的复杂映射 + 含位置不可观测的 twist,直接监督也学不会(~随机)。这道墙嵌入无关、单帧无解(需时序/额外信号/先验,见 [[TWIST_INVESTIGATION]])。

---

## 四、和文献一致的落地判断

主流(H2O/OmniH2O/GR00T/ExBody)**不做**这种共享码 any→any 旋转翻译:它们**跟踪位置/关键点 → 目标端 IK 解关节角**。我的实验独立复现了为什么——位置可迁移、旋转不可迁移。

**两条路:**
1. **工程可落地(替代GMR)**:学位置/关键点迁移 + 目标骨架 IK。绕开旋转墙和翻译对齐墙。但要注意:我这套共享码连位置翻译都没做好(~20cm),position路线要用**专门的监督retarget网络**(不是共享码自编码器)重新验证ceiling。
2. **研究难题(any→any共享码)**:目前未破。需要比 L2/InfoNCE 更强的具身无关约束(cycle-consistency 完整实现、对抗判别器、或去掉编码器源身份),且旋转要接时序。

---

## 五、⚠️ 指标 bug 教训(重要)

一度得出"位置翻译秒到0.00cm"的错误结论,根因:临时脚本用了 `tensor.norm(-1)` —— 这是 **p=-1 范数(整个张量一个标量)**,不是 `tensor.norm(dim=-1)`(逐关节欧氏距离)。修正后真实值是 25cm(基线),翻译其实失败。**主训练脚本用的是正确的 `dim=-1`,其数字有效。** 教训:位置/距离一律 `.norm(dim=-1)`,诊断脚本也要过基线校准(mean-pose baseline)。

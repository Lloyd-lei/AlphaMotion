  * BIT BUDGET 62.69 bit/s in BOTH arms, asserted before the first step:
      jepa    = 8 path latents + 1 time register = 9 x 6x5 FSQ
      maskfsq = 9 time-local group codes         = 9 x 6x5 FSQ
    (a literal per-FRAME FSQ would be 418 bit/s = 6.7x arm 1; matching the
     budget at 60 registers forces 2.09 bits/frame, a degenerate code. 9
     contiguous groups of 7/6/7/7/6/7/7/6/7 frames is the fairest matched
     configuration: identical register count, dims and levels, so the only
     difference is WHERE the bits live.)
  * Input: 6 key joints' 6D rotations PLUS velocity + SG(5,2) angular
    acceleration residuals on every frame. NO JERK (R10: -11..-0.3 dB SNR).
  * Loss: path integral + Riemann per-segment + velocity + multires + frame.
  * Time-scale augmentation ON. 16 of 18 embodiments trained; both G1s held
    out for the zero-shot row. pal_talos uses the FIXED alias spec.
  * THE ONE LOSS ASYMMETRY, architecture-forced: the invariance pair is a
    non-uniform WARP for jepa (a global path code should survive it) and a
    pure frame-rate change for maskfsq (a time-local code stream cannot
    survive a warp that moves content between its own groups; demanding it
    would only force the codes to discard the content). Row (ii) must be
    read with that in mind — it measures an architectural property.
  * arm 1 additionally carries the JEPA latent-prediction term (--w_jepa),
    which is what makes it a JEPA rather than a conditional VQ-VAE.

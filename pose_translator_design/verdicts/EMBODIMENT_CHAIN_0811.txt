VERDICT: hypothesis refuted, and hard. One hop puts the integer code at 0.605
against a chance floor of 0.567 — 3.8 points above unrelated motion. Equator
tokens agree 0.0%. Hops 2-5 add nothing: the damage is entirely in hop 1 and
then saturates. The code is not an embodiment-invariant object; it is
re-drawn the moment the pose passes through another body.

THE APPARENT CONTRADICTION, AND WHERE IT LANDS: translation itself is fine
(7-20 cm, visually correct). So the MOTION survives while the CODE does not.
This is a known, documented failure that was never switched on: train_dual.py's
N3e option says verbatim "encode(decode(z)) explodes even same-body (round-trip
error ~8.7 -> ~38.8 deg), which kills any synthetic-data pipeline" — and C1's
config has reenc_consistency = 0.0. lloyd's chain test independently
rediscovered it and, for the first time, quantified how fast it dies: one hop.

CONSEQUENCES
 * any pipeline that feeds decoded output back into the encoder is unsound with
   C1: synthetic-data generation, iterative refinement, chained retargeting,
   and (importantly) the autonomous rollout in phase_space.py, which re-encodes
   its own decoded frames every chunk. Part of the B3/B6/B7 drift we spent the
   evening on may be THIS, not a prior-side defect. That reframes the B-series
   result and must be tested before the E17 RL run is designed around it.
 * the fix exists and is one flag: retrain/finetune the spatial stack with
   --reenc_consistency > 0. Cheap to try as a decoder-side finetune first,
   using the same frozen-lattice surgery that was already validated today.

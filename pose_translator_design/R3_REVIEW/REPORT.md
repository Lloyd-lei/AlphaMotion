## 一、最终结论(修好 bug 之后,正确表示下的真实结果)

1. **跨具身翻译成立。** 人体 SOMA → 机器人 G1 的翻译,位置误差 **2.59cm**、旋转 **9.1°**,和"直接重建 G1"(2.43cm / 8.9°)几乎相同——**翻译质量 = 重建质量**。四个方向(人↔人、人↔机器人)全部work。
2. **twist 不是问题。** 人体 twist 残差 ≈ **0°**(修 bug 前是 ~57°)。
3. **共享码是具身无关的。** 同一动作的 SOMA 码和 G1 码几乎相同(code_align_dist **0.019**),所以"把源编码解到目标身体 = 直接重建目标身体"。
4. **架构**:拓扑无关图编码器(hop图偏置 + SigLIP关节名语义)→ 双 FSQ(位置一路码、旋转一路码)→ 拓扑无关解码器;跨具身用 InfoNCE 对比对齐(同动作码相吸、异动作相斥)。全局帧 SE3 目标。

## 二、⚠️ 关键更正:一个 bug 制造了本轮几乎所有"墙"

**本轮大部分时间得出的悲观结论(twist 是位置不可观测的硬墙、双FSQ只救机器人、跨具身翻译失败~22cm)——基本都是一个 bug 的假象。**

- **Bug**:`matrix_to_rot6d` 用 `R[...,:,:2].reshape(...,6)` 把旋转矩阵的两列**行主序交错**了,而 `rot6d_to_matrix` 按"前3=第0列、后3=第1列"读——两者约定不一致,**每个旋转在编码时就被打乱**。数据管线里 `local6d=matrix_to_rot6d(...)`,FK 再用 `rot6d_to_matrix` 误读 → 局部旋转乱 → 全局位置也乱。
- **怎么发现的**:lloyd 一直追问"人体 twist 为什么降不下去",逼我做了个 per-joint MLP identity 测试——**一个 6d→MLP→6d 的自编码器连 identity 都学不会(90°)**。这不该发生,顺藤摸瓜查出 `geodesic(R,R)`(经 6d round-trip)= 177°(应≈0),定位到列交错。
- **修复验证**:6d round-trip 从 177° → **0.08°**;同一个 MLP identity 从 90° → **0.82°**;整模型人体旋转从 91° → **~6°**,twist 残差 57° → **0°**。
- **影响**:本轮所有旋转/位置定量结论,凡是修复前(D_dual / DS / DC / RD / v5 / v8 等)的,**全部作废**;只有 `FIX_*` 两个 run 是正确表示下的有效结果。

(另外还纠正过一个诊断脚本里的 `.norm(-1)`(p=-1范数)vs `.norm(dim=-1)`(逐关节距离)的错,主训练脚本没这个错。)

# ARCH V4 — 时序动作 token 完整架构总览（lloyd 定向,2026-08-05 晚定稿草案）

一句话:**三层码本,一个掩码,零扩散**。空间层管"身体怎么摆",时序层管"动作怎么展开",生成层管"听懂指令挑动作"。SE3 约束和 prompt 都是序列里的 token,不走旁路。

```
[prompt 词] [SE3 token] │ [粗动作token T1] [T2] ... │ (展开器) → [每帧骨架码] → 任意骨架解码 → 投影 → 执行
└── 同一个 self-attention 序列(同一种语言) ──┘              └─ WBC 共享的潜空间 ─┘
```

---

## 一、三层各自是什么、怎么训

### 第 1 层:空间骨架码(已有,E19 系)
- 每帧 × 每身体 → 双流 FSQ 码(K=128×13维×2)。已验证:跨具身同帧 AUC 0.960、零样本新机器人可用。
- **不重训**,除非 E26 判修复缓存显著更好(今晚出)。

### 第 2 层:时序动作 token(要建,核心新东西)
**编码对象:第 1 层的码序列**——不是原始关节数据。这是"跨具身还能不能保证"的答案:
- 码空间本身已经基本身体无关(AUC 0.960),所以在码流上学的时序 token **天生继承跨具身性**——"迈一步"对人和 G1 是同一串码型。
- **裂缝要诚实**:不变性不完美(kNN 仍能 71.6% 认出身体、talos 自成孤岛)。时序 token 会继承这些泄漏。**补法**:时序编码器训练时加同一套 InfoNCE(配对身体的码流互为正例)——机器已有,搬过来即可。

> **⚠ 2026-08-06 修订(P1 失败 + 跨领域文献)**:下面的 8 寄存器/2秒 ≈ 56 bit/s **低于率失真下界**(粗估 128-192 bit/s)。对照 stable-codec:**FSQ 配置与我们完全相同(6维×5档=15625),但 25 token/秒且保留时间轴**;我们 4 token/秒且无时间索引。文献一句话总结:**动作类别是"词",步态相位是"韵律"——当前预算只够装词。** 另:逐帧回归/CE 的最优解就是时间平均(Mathieu 2015 已证),全局池化在音频/视频领域**无一例外被弃用**。P1c 正在测:①argmax→采样(可能部分是解码假象) ②提高 token 率到 16-24/窗 ③保时间轴架构(卷积/频率绑定)。
**训练方式(OAT 式有序,这就是"要不要对 skeleton token 做 mask"的答案)**:
1. 取 **2 秒窗口**(60帧@30fps;E13 教训:16 帧太短,步态周期 1-1.2 秒装不下)
2. Perceiver 寄存器交叉注意读整个窗口 → N 个**有序**寄存器 → FSQ
3. **前缀训练**:每步随机抽预算 n∈{1,2,4,8},**把 n 之后的寄存器遮掉**,强迫只用前 n 个重建整窗
4. **重建目标 = 每帧骨架码的档位,用交叉熵**——不是 MSE。一石二鸟:离散目标没有"回归到均值",**顺手治幅度压缩**(回旋踢抬不起腿那个病)
5. 时间缩放增广:窗口按 0.5×~2× 重采样喂进去,逼粗 token 对速度不变(速度另走通道,见三)

所以:**mask 的是时序寄存器(前缀预算),不 mask 骨架码——骨架码是重建目标。** 生成时只预测时序 token,骨架码由展开器从时序 token 解出(你说的"spatial 是 temporal 的子集"就落在这一步)。

### 第 3 层:生成器(掩码补全,MaskGIT+OAT 调度,无扩散无逐帧AR)
- 序列 = `[prompt前缀] [SE3 token们] [窗口1的粗token...细token] [窗口2的...]`,全在一个 self-attention 里
- 训练 = 随机遮时序 token,预测被遮的(交叉熵)。掩码族即产品用法:遮未来=续写;全遮=纯文本生成;遮中间=补间
- 生成 = 按 OAT 块调度先粗后细,**粗 token 约束细 token,复制退化无路可走**
- **OAT 硬警告**:第 2 层的预算调度(1,2,4,8)必须现在定死,生成器按同一调度解码。**事后改调度 = 重训**(实测掉 13 个百分点)

## 二、逐问回答

### 时序编码的是什么?
第 1 层码流(取整前的连续 z,或整数码——待 P1 探针裁决哪个更好)。

### 跨具身还保证吗?
保证的来源:码空间共享。**新增风险仅一处**:时序层可能放大身体泄漏 → InfoNCE 压制 + 用判官探针那套方法验收(时序 token 的身体可识别率要 ≤ 帧级的 71.6%)。

### 速度怎么控制?(2026-08-05 深夜修订:lloyd 定案"功能学出来,不要人为设计")
三件套:
1. 粗 token 编"归一化时间里的动作形状"(缩放增广保证)
2. **时长 = 预留一个寄存器席位,码表由 FSQ 自己学**——撤回原 32 档 log 手设刻度。我们只定"有这个座位",不定"座位上坐什么"
3. 细 token 承载窗口内的时间弯曲(接触瞬间慢这种)——OAT 的细层天然位置
先决条件 = 时间缩放不变性诊断(P0,跑中)。

### prompt 怎么进来、怎么生成动作?
- prompt 词向量作**前缀 token**进同一序列(in-context,无 x-attn 翻译层)
- 生成:给 prompt、全遮时序 token → 块调度解码 → 展开 → 投影 → 执行
- **数据是硬约束**:文本-动作配对只有 HumanML3D 量级。启动策略:先用动作族 regex 标签当穷人版 prompt 预训练,配对数据进来再细调
- 编码器:近期 SigLIP(关节名)+任意(prompt);**重训时统一到 Qwen3-Embedding-0.6B**(对决结论)

### SE3 token 怎么设计?(2026-08-05 深夜修订:统一为"约束=没被遮的格子")
**统一抽象:一切都是补全问题里的一个格子。** 约束不是指令,是观测——"左脚 t=2.0s 在这里"就是 (关节×时间) 网格里一个**没被掩码的格子**,和训练时随机可见的格子同机制。终止=词表里学出来的 <eos> 条目;读出=Perceiver 寄存器(本来就是学的);时长=学习式寄存器席位。
- **学不掉的只有两样**:I/O 边界(连续位姿→Fourier 特征,如同 ViT patchify)和训练压力本身(我们设计"什么可见",模型学"意味着什么")
- 约束最干净的落点在**展开器层**(它有每帧每关节的格子)。生成器层被压缩无格子——P2 先跑**纯格子路线**(生成器盲选+best-of-N按约束满足度挑),不行再加约束摘要视图(P2 消融裁决)
- 谁都能发:VLA/SLAM/规划器往网格里"点亮一个格子"就是下了约束
- **最终精度仍由投影层保证**(E25 失败后投影暂不可撤)

## 三、预注册训练计划

| 阶段 | 内容 | 成本 | 通过判据(预注册) |
|---|---|---|---|
| **P0 诊断** | ①时间缩放不变性(现 tokenizer 0.5×/2× 重采样码变多少) ②粒度探针:4帧chunk掩码预测准确率 | CPU半小时 + 1 GPU日 | ①码变化小→速度方案成立 ②遮50%猜对>60%→时序层有地基 |
| **P1 时序tokenizer** | OAT式有序,2秒窗,前缀{1,2,4,8},交叉熵重建,缩放增广,InfoNCE | 2-3 GPU日 | ①**前缀1解码肉眼是可辨认的粗动作(viser验收)** ②等比特打赢无序对照 ③时序token身体可识别率≤71.6% ④重建≤帧码底线+2° |
| **P2 生成器** | 掩码补全+块调度,先用动作族标签当prompt | ~1周 | ①无复制退化(码多样性) ②给1个SE3 token能弯动作方向(可视化) ③续写模式不漂 |
| **P3 可跟踪率** | 解码动作→开源WBC(BeyondMimic/SONIC类) | 并行起步 | 建立数字;WBC共享潜空间层的生死线 |

数据侧并行:舞蹈/武术/体操采购(R8 结论:唯一能涨维度的东西);Franka+动物别名表(各几十行)。

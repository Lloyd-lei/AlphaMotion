# 文献地图：文本 + SE3 约束的跨身体动作生成

日期 2026-08-05。给 lloyd 做架构决策用。

怎么读这份东西：每一章先说别人做了什么，再说哪些是真的做完了、哪些是所有人都卡住的。
第五章是给我们的具体建议，每条都挂着出处和我们自己的数字。第六章说清楚我们哪里领先、哪里在重复造别人的轮子。

我们手上的数字（下面反复引用）：
- tokenizer：每关节 6D 全局旋转 + 根相对位置 + 关节轴/限位描述 + SigLIP 关节名 + 图偏置注意力 → 双 Perceiver → 双 FSQ。一套码本管 20+ 骨架，对没训过的机器人（AgiBot A3/X2，直接读厂商 MJCF）零样本可用。
- 单帧稀疏 SE3 约束已通：遮住大部分关节，模型补全全身，再用阻尼最小二乘投影把被命令的关节钉到微米级，同时满足关节限位，违规 0%。模型比纯 IK 好 2–2.5 倍，中间档（4 个命令 / 13 个自由关节）差距最大。
- 时序层还没有。裸自回归退化成 93.9% 复制上一帧的 token；分块 latent 扩散抖。
- 30fps 下相邻帧冗余 77.7%（R7）。动作的本征维度只有约 8（单帧）到 8.7（32 帧）（R8），MNIST 约 13、CIFAR 约 26、ImageNet 约 40。
- 相位探针（16 帧拆慢内容 + 快相位）没打赢"冻结第一帧"。

## 一、文本 + 空间约束的动作生成

### 1.1 一共只有五种注入方式

所有论文都落在这五类里，剩下的是工程细节。

1. **补洞（inpainting）**：每一步去噪后，把已知关节的数值硬写回去。零训练成本。缺点是接缝跳变。MDM、GMD、Kimodo。
2. **梯度引导（classifier guidance）**：定义一个可微损失，每步推一下样本。软的。每步多一次反传，很慢。GMD、OmniControl。
3. **ControlNet 分支**：复制一份主干，零初始化，吃控制信号，输出残差加回去。推理快，但还是软的，每种控制要单独训。OmniControl、MotionLCM、InterControl、ACMDM、KV-Control。
4. **推理时优化 latent**：冻住模型，一路反传优化初始噪声或 VQ latent，直到约束损失接近 0。精度最高，最慢。DNO、TLControl、MotionLCM-V2。
5. **掩码 token + logit 手术**：在 VQ token 上跑掩码生成，然后把 logits 往"解码后关节位置对得上"的方向推。MaskControl / ControlMM。

### 1.3 真的解决了的

- **稀疏关键帧精度已经饱和。** 从 MDM 的 60 厘米降到 0.4–1 厘米。MaskControl 在单关键帧下是 0.10 厘米。
- **快和准不再矛盾。** ACMDM 2.51 秒达到 1 厘米，KV-Control 1.5 秒达到 0.4 厘米。OmniControl 那个 81 秒的时代结束了。
- **控任意关节是常规操作。** InterControl 控全部 22 个。
- **表示的问题有答案了。** ACMDM（arXiv 2505.19377，作者就是 OmniControl 那批人）说得很直接：HumanML3D 那套根相对、冗余的 263 维表示，就是空间控制做不好的根因——你没法把一个全局位置补进一个相对速度的表示里。换成**绝对全局坐标 + 训练时就教条件**，去掉推理时引导，误差比 OmniControl 低 3.4 倍、速度快 32 倍。CondMDI（SIGGRAPH'24）单独做过消融：补洞会跳、引导还是会跳、训练时教进去才平滑。

### 1.4 所有人都卡住的

- **没有一个方法是硬约束。** 全是软的。没有投影层、没有 KKT、没有可行性保证。DNO 和 TLControl 能把误差优化到 0，那是收敛不是保证，而且要 3–5 分钟。
- **没有任何一篇文生动作论文管关节限位。** 一篇都没有。生成的姿态可以是人体做不出来的，没人测。
- **密集轨迹跟踪会崩。** MaskControl 自己的消融：1 个关键帧 0.10 厘米 → 25% 帧 1.68 厘米 → 全密集 1.64 厘米。**差 16 倍。** 大家都报稀疏的那个好看数字。
- **硬约束的唯一解法是事后 IK，而且是顺嘴一提。** Kimodo 原话：可以做轻量后处理让它精确命中用户约束，不会严重掉质量。然后他们**把这步从所有实验里排除了**。所以全领域的数字系统性地低估了"加一步投影"能到什么水平，也没人量化过投影的真实感代价。
- **SE(3) 里的旋转基本没人做。** 只有 Kimodo 报了末端旋转误差 4.18°。其他全是纯位置。
- **快的自回归方法一个米制误差都不报。** DART、CLoSD、ARDY、COMET，全没有。这是个空位。
- **跨骨架的可控生成基本是空白。** Kimodo 支持 27 关节 / SOMA / SMPL-X / Unitree G1，但它是**离线重定向数据集，每个骨架训一个模型变体**，不是一套共享表示。

### 1.5 自回归那边的退化问题，别人怎么处理的

- **T2M-GPT**：误差累积是它的公开缺陷。
- **MoMask**：干脆不做自回归，改残差 VQ + 双向掩码并行解码，绕过漂移。
- **MotionStreamer**（ICCV'25）讲得最清楚。两个补丁：(a) 用**连续因果 latent** 代替离散 token，理由是离散化的信息损失会放大误差累积；(b) **两次前向训练**——第二遍把一部分真值 latent 换成模型自己生成的，等于并行版的 scheduled sampling。BABEL 长时 FID 15.7 对比 T2M-GPT 改版的 39.5。**但对我们最关键的一句：MotionStreamer 明确说它做不了空间控制**，因为流式范式靠单向建模，天生不支持中间 token 的编辑和补间。
- **DART**（ICLR'25）：每个 primitive 带重叠的历史帧，这就是它的抗漂移机制。它承认的失败模式是**重复**——长 rollout 要么自然重复，要么在某个边界状态附近来回抖。
- **CLoSD**（ICLR'25）：把物理仿真器放进环里。RL 跟踪器执行扩散规划器的短时计划，**仿真出来的结果（不是预测）**作为下一轮的前缀。误差压根没机会累积。3500 FPS。
- **MoScale / Next-Scale AR**（arXiv 2604.03799）给了最贴我们的诊断，原话大意：动作的短期动力学高度可预测，每个未来姿态从很短的历史就能推出来，模型于是靠吃这个短程可预测性来降 loss，而不是去学全局时间结构。**这就是我们 93.9% 复制的教科书解释。** 他们的解法是不预测下一帧，而是**预测下一个尺度**——残差 VQ 分 4 级，HumanML3D 上序列长度是 (6, 12, 24, 49)，共享 512 码本，从粗到细自回归。HumanML3D 上 FID 0.046（MoMask++ 0.072），R@1 0.540，0.28 秒。
- 还有一条：VQ 编码器用的是时序卷积，天然是双向依赖，而 next-token AR 假设单向因果。**这个错配本身就是问题。**

## 二、动作 token 进语言模型

### 2.1 一句话结论

**人体动作和机器人两边独立地收敛到同一个答案：一个 token 等于一个 chunk，不是一帧。** 最强的量化证据在 FAST 那篇里。

### 2.2 人体动作侧的事实标准

| 工作 | 量化器 | 码本 | 时间降采样 | 每 token 帧数 | 每秒 token |
|---|---|---|---|---|---|
| T2M-GPT (2023) | VQ + EMA + 死码重置 | 512 × 512 维 | 4 | 4 | ~5 @20fps |
| MotionGPT (NeurIPS'23) | VQ | 512 | 4 | 4 | **5**（明说 20fps→5fps） |
| MotionGPT (AAAI'24) | VQ | — | 4 | 4 | ~5 |
| MotionLLM / Motion-Agent (ICLR'25) | VQ（多人用 RVQ 6 层） | 512 | 4 | 4 | ~5 |
| MoMask (CVPR'24) | **RVQ 6 层** | 每层 512 | 4 | 4 | 5 × 6 层深 |
| MMM (CVPR'24) | VQ + 掩码 | — | ~4 | ~4 | ~5 |

**几乎没人用逐帧 token。** 统一答案是 **1 token ≈ 4 帧 ≈ 200 毫秒 ≈ 每秒 5 个 token**，保真度靠**码本深度或大小**买，不靠提高时间分辨率。

### 2.3 2025–2026 的转向：FSQ / LFQ 和更大的码本

- **ScaMo**（CVPR 2025，arXiv 2412.14559）：**用的就是 FSQ**，只靠一个重建损失，加文本前缀自回归 Transformer。他们确认了动作生成的 scaling law。**我们选 FSQ 和 SOTA 一致，不是野路子。**
- **Being-M0 / MotionLib**（ICML 2025）：2D-LFQ，把动作序列当单通道图像，等效码 2^16 = 65536。重建 MPJPE 45.6 毫米。他们的结论是**瓶颈是 token 空间太小，不是模型不够大**。挂到 LLaMA2-13B 上当额外词表。
- **MotionMillion**（2507.07095）：2M 序列 / 2000+ 小时，选 FSQ 就是因为无码本、不会塌。MPJPE 45.5 对 ScaMo 的 88.9。生成器 1B → 7B，FID 31.3 → 10.3。**一个坑要记下来：原味 FSQ 规模上去以后会抖**（离散化信息损失），他们用小波预处理修好，加速度误差 6.0 → 4.0。
- **码本大小的干净消融**（2606.27547）：K=4096 的 FID 只比 K=2048 好一点点（0.093 vs 0.094），但**K=4096 只有约 24% 的码在用，K=2048 有 76%**。
- **双粒度消融**（2512.24100，Think Before You Move）直接打我们的问题：执行 token 用 1× 分辨率 MPJPE 是 16.6，1/4× 掉到 30.3；**但 1/4× 那个模型的生成 FID 明显更好**。推理 token 固定执行层为 1× 时，1/4× 最优（FID 0.040），1/2× 抽象不够，1/8× 丢时间粒度。他们的结论：**tokenizer 对生成好不好，取决于它怎么处理时间结构，不是重建保真度。**

### 2.4 机器人侧 —— 最重要的部分

**RT-1 / RT-2**：每个动作维度均匀分 256 个桶，每维每时刻 1 个 token。RT-2 更进一步，直接映射到 VLM 已有的文本 token 空间，**不扩词表**（PaLI-X 借用最少用的 1000 个 token）。

**OpenVLA**：同样 256 桶，**覆写 Llama 分词器里最少用的 256 个 token**（因为 Llama 只支持加约 100 个特殊 token）。公开的四个毛病：
1. 每个动作 7 个串行 token，卡在 **~5 Hz**（实测 136.2 毫秒 / 7.34 Hz）。
2. 没有 action chunking，做不了高频控制。
3. 离散化丢细节。
4. **频率不匹配**——在低频的 BridgeV2 和 RT-1 上还行，在高频的 DROID 上就学不动。

**OpenVLA-OFT** 的修法是**放弃离散 token**：并行解码 + 连续动作头 + L1 回归。31.1 毫秒 / 32.14 Hz。这是"离散 token 不是免费的"最强证据。

**FAST（Physical Intelligence, 2025，arXiv 2501.09747）—— 核心参考**

*为什么逐时刻分桶在高频下会挂，机理是这样的*：token i 的学习信号正比于"给定前面所有 token 后，T_i 还带多少新信息"。信号是平滑的，采样频率一升，每步的变化就成比例变小，这个边际信息**趋近于零**。模型于是靠**复制上一个 token**这个平凡策略就能把交叉熵压得很低，训练直接塌。**这是学习信号的失败，不是表示能力的失败。**

他们的教学实验：同一个信号，25 步/序列时 MSE 很低；800 步/序列时彻底失败，模型退化成复制上一步。真实任务上，**朴素分桶在 20 Hz 以上开始不行，100 Hz 以上迅速恶化；FAST 从 25 Hz 到 800 Hz 重建 MSE 都很低。**

*管线*：
1. 归一化，用每维的 **1% 和 99% 分位**映到 [-1,1]（分位数抗离群点）。
2. **DCT**，每个动作维度沿时间轴独立做。选它是为了能量集中，跟 JPEG/MP3 同理。
3. 量化：`round(γ · C)`，默认 **γ=10**。大部分高频系数直接归零。
4. **按列展平**——所有维度的最低频系数排前面，然后次低频。这样自回归生成就是**先出整体形状再出细节**，天然从粗到细。
5. **BPE**，默认词表 1024。它的活是吞掉那一大串零。

*压缩比（每 1 秒 chunk 的 token 数）*：

| 数据集 | 频率 | 朴素 | FAST | 倍数 |
|---|---|---|---|---|
| BridgeV2 | 5 Hz | 35 | 20 | 1.75× |
| DROID | 15 Hz | 105 | 29 | 3.6× |
| Table Bussing | 20 Hz | 140 | 28 | 5.0× |
| T-Shirt Folding | 50 Hz | 700 | **53** | **13.2×** |

**最值得抄进设计文档的一句：FAST 每条手臂每秒约 30 个 token，基本跟控制频率无关。** token 数跟着动作的内在复杂度走，不跟着采样率走。朴素分桶的 token 数随赫兹线性涨，高频下几乎全是冗余。

*FAST+（通用 tokenizer）*：100 万个 1 秒 chunk，单臂/双臂/移动机器人都有，所有动作**零填充到 32 维**。在每一个没见过的留出数据集上都拿到 ≥2× 压缩。当成 HuggingFace 上的黑盒 tokenizer 发布。

*训练速度*：π₀-FAST 比扩散版 π₀ 少用 **5 倍 GPU 小时**就追平。

*代价*：自回归解 30–60 个 token 要 **~750 毫秒/chunk**，π₀ 的 10 步流匹配只要 ~100 毫秒。他们自己把这列为局限。

*消融*：去掉 BPE 保留 DCT，还是比朴素分桶强，但会退化——没有 BPE，模型要花几百个自回归步去预测冗余的零。超参**没有按数据集调**（到处都是 γ=10、词表 1024），他们拿这点对比学习式 VQ 压缩器需要逐数据集重训。

**π₀.₅ 的设计教训（最该抄的）**：**预训练全用离散 FAST token（简单、可扩展、省算力），后训练再接一个流匹配动作专家换推理速度。** 他们原话是 FAST token 训练比纯扩散训练更省算力。另外还有 **knowledge insulation**——把动作专家到 VLM 权重的梯度掐断，动作专家推理时能读 VLM 各层，训练时污染不了它。这直接回答"加动作 token 会不会伤文本能力"。

**FAST 之后的 2025–2026**

- **BEAST**（NeurIPS'25）：B 样条 tokenizer，**完全不训练**，最小二乘拟控制点再 8 bit 均匀量化。**100 步序列约 5 个 token**，比分桶少 4–8 倍。固定长度所以能并行解码，B 样条连续性保证 chunk 之间没有接缝。CALVIN ABC 99.8%（OpenVLA 91.3%），617 Hz。**消融里离散比连续好 12.7%**——这是"FSQ 不用 AE"的直接支持证据。
- **FASTer**（2512.04952）反过来说学习式 tokenizer 更好：**码本 4096，token 利用率 100%；FAST 有效 2048 但只用了 48%**，还有一个 token 占了 10% 的频率。他们的主张：**码本激活是否均衡（归一化熵）比重建误差更能预测泛化。** 单臂 20 token/chunk，全身 32 token/chunk。
- **ActionCodec**（2602.15397）是最接近受控研究的：**拓扑稳定性 > 绝对保真度**。相邻 chunk **70% 时间重叠 → 500 步内成功率 33.4%**，朴素 VQ-VAE 8.2%，FAST 2%。推荐工作点 **词表 2048、每 chunk 16 个 token**。还有一条对我们很重要：**非因果（独立）tokenizer 优于因果 tokenizer**，因果的会过度依赖历史，产生"时间幻觉"。
- **X-Tokenizer**（2606.14752）：对**相对本体感受锚点的 delta 动作**做 tokenize 以便跨身体复用。语义残差量化 4 级 × 2048 码，**64 帧 chunk 用 16 个 latent 槽**。不对称设计是关键：第 1 级用掩码动作建模监督，形成粗粒度的"意图语言"；2–4 级纯重建，管执行细节。2.4M 轨迹 / 171 个机械臂系列。

### 2.5 词表怎么并进 LLM

| 模型 | 策略 | 数字 | 要不要重训 LLM |
|---|---|---|---|
| Chameleon | 单一统一 BPE 词表含图像码 | 图像码本 8192；512×512 图 = 1024 token；总词表 65536 | **从零训**，9.2T token |
| Emu3 | 视觉码本拼到文本词表后面 | 152064 + 32768 = 184622 | **从零训** |
| Transfusion | **不用图像 token**，连续 VAE patch + 扩散损失 | — | 联合训 |
| Janus | **解耦编码器**：理解用 SigLIP，生成用 VQ | — | 基于 DeepSeek-LLM |
| MotionLLM | 加 **514 个 token** 到 Gemma-2b（256000→256514），**文本嵌入和原输出层冻住**，LoRA rank 32 只动 1–3% 参数 | 39.2M 可训参数 | 不用 |

**Chameleon 的 logit 漂移是最该记住的坑。** 权重跨模态共享，而 softmax 有平移不变性，所以每个模态都能靠**微微抬高自己的 logit 范数**来降自己的 loss。不同熵的模态（文本高熵、图像 token 低熵）之间会变成范数军备竞赛。前期无害，**等激活值超出 bf16 表示范围就炸——而且炸得很晚，训练进行到 20–30% 才炸**。最难受的一点：**稳定配置和不稳定配置的困惑度看不出差别**，loss 曲线一模一样，直到发散。

修法按他们的顺序：**QK-Norm**（在 attention softmax 前对 q、k 做 LayerNorm，直接压住范数增长）为主；34B 还要加 **norm 重排**（Swin 式后置 norm）；**z-loss** 系数 1e-5；7B 加 dropout 0.1。

**能加多少新 token**：256 个（覆写，OpenVLA/RT-2）、**约 514 个（追加 + 冻文本嵌入 + 冻原输出头 + LoRA，MotionLLM，记录最完整、最保守）**、1024 个（FAST BPE，塞进 PaliGemma 是常规操作）、65536（Being-M0 的 2D-LFQ 进 LLaMA2-13B，这是"往预训练 LLM 上扩"的最大记录）。Chameleon 的 65536 和 Emu3 的 32768 **都是从零训的，不能当作预训练 LLM 能吸收这么多的证据**。

好消息是 Chameleon-34B 在几个纯文本 benchmark 上打过 Llama-2-70B，尽管一半训练 token 是视觉的。但原因是**文本仍然占 token 预算的多数**，不是扩词表免费。

**反面证据**：Transfusion 用 21.8% 的算力就追平 Chameleon 的图生文。它的诊断是量化本身就是信息瓶颈。这是"把连续模态硬塞进离散词表要付代价"的最强论据，也是 π₀.₅ 那套"预训练离散、后训练连续"混合方案现在被认为是最优解的原因。

## 三、时间分解 / 相位 / 原语

### 3.1 我们那个负面结果：文献预测得到，而且有一个更具体的原因

**16 帧不到一个步态周期，压根没有"快相位"可提。** 这条线上所有认真的方法都用约 2 秒的窗口：DeepPhase 用 N=121 帧 @60Hz（中心帧前后各 1 秒）；WalkTheDog 同样；PHASOR（2026）明写 T=121 帧 @60fps 约 2 秒。人走一步是 1.0–1.2 秒，也就是 60–72 帧 @60Hz。

**16 帧的 rFFT，频率分辨率是 60/16 = 3.75 Hz，1 Hz 的步态整个落在第 0 个 bin，也就是直流项。** 数学上就没有可分的频率。

DeepPhase 自己的消融也说过：不走 FFT 层而直接学周期参数，相位、幅度、频率全都沿时间乱抖，manifold 一片噪声。

### 3.2 更一般的原因：在我们那个时长上，"冻结第一帧"就是零速度基线，而它出了名地难打

**Martinez et al., CVPR 2017**，"On Human Motion Prediction Using RNNs"（arXiv 1705.02445）。Human3.6M 上 80/160/320/400 毫秒的平均角度误差：

| 方法 | Walking | Eating | Smoking | Discussion |
|---|---|---|---|---|
| ERD | 0.93 1.18 1.59 1.78 | 1.27 1.45 1.66 1.80 | 1.66 1.95 2.35 2.42 | 2.27 2.47 2.68 2.76 |
| LSTM-3LR | 0.77 1.00 1.29 1.47 | 0.89 1.09 1.35 1.46 | 1.34 1.65 2.04 2.16 | 1.88 2.12 2.25 2.23 |
| SRNN | 0.81 0.94 1.16 1.30 | 0.97 1.14 1.35 1.46 | 1.45 1.68 1.94 2.08 | 1.22 1.49 1.83 1.93 |
| **零速度基线** | **0.39 0.68 0.99 1.15** | **0.27 0.48 0.73 0.86** | **0.26 0.48 0.97 0.95** | **0.31 0.67 0.94 1.04** |
| 他们最好的模型 | 0.28 0.49 0.72 0.81 | 0.23 0.39 0.62 0.76 | 0.33 0.61 1.05 1.15 | 0.31 0.68 1.01 1.09 |

看最后两行：**在 smoking 和 discussion 上，零速度基线在每一个时间点都打赢了他们自己的模型。** "两帧滑动平均"这个基线也打赢了全部三个已发表的 RNN。原话：零速度预测是一个简单但很难打赢的基线，大幅超过当时的 SOTA。

**siMLPe**（WACV 2023）补刀：**0.14M 参数**（对手 >2M）打赢所有 transformer/GCN，在 H3.6M、AMASS、3DPW 上都是。只用 DCT + 残差位移 + 速度损失。**短时预测几乎不需要容量。**

### 3.3 AMASS 确实是走路和过渡为主

BABEL（CVPR 2021）标注了约 43.5 小时的 AMASS：28055 条序列标签，260 个动作类别。**出现最多的动作是 "transition"（过渡），18447 次。** 分布是 Zipf 的：第 50 名（catch）417 次，第 100 名 86 次，**第 200 名（disagree）8 次**。最大的标签簇是"走路变体"和"全身直立变体"。约 40% 的时长是没标签的零碎移动。

**这和我们 R8 的读数完全一致**：走路 7.1 维、伸手 7.3 维，跳舞 15.4、跳跃 14.5。**跳舞是走路的两倍。**

### 3.4 相位方法在什么数据上真的有用

DeepPhase（SIGGRAPH 2022 最佳论文）自己的表 2，每秒关节旋转量（MANN / LMP / DeepPhase）：

| 技能 | MANN | LMP | DeepPhase | 相对 LMP 的提升 |
|---|---|---|---|---|
| 双足走路 | 43.6 | 49.8 | 51.2 | **+2.8%** |
| 芭蕾 | 38.4 | 46.9 | 48.2 | **+2.8%** |
| 四足走路 | 159.7 | 173.2 | 195.7 | +13% |
| 嘻哈舞 | 97.8 | 98.8 | 114.4 | +16% |
| 手臂挥打 | 27.6 | 31.2 | 41.4 | +33% |
| 狗尾巴（走路时） | 9.4 | 10.9 | 15.8 | +45% |
| **足球带球** | 76.4 | 93.5 | **149.8** | **+60%** |
| **表现性舞蹈** | 74.2 | 53.9 | **92.1** | **+71%** |
| **单/双脚跳** | 67.3 | 36.1 | **88.5** | **+145%** |
| **狗尾巴（静止时）** | 0 | 0 | **14.2** | 从无到有 |

**普通双足走路和芭蕾是整篇论文里最小的两个提升。** 在四足走路的脚滑指标上，DeepPhase 甚至输给基于接触的 LMP（0.522 vs 0.514）。

**有用的地方全在"肢体之间周期不同步"**：100STYLE 里手臂和腿周期不一样；单脚跳；狗尾巴；足球带球（球本身带来第二个节律）。相位通道数也说明问题：**普通双足走路 5 个通道就够，风格化要 10 个，舞蹈 8 个。走路需要的最少。**

### 3.5 WalkTheDog（SIGGRAPH 2024）—— 对我们最有教育意义的一张表

- manifold：Ψ(A, φ) = A⁰sin(2πφ) + A¹cos(2πφ)。**单个标量相位** φ，幅度 A 来自一个**有限的学习码本**，所以 latent 空间是 R^d 里一堆互不相交的椭圆，一个码一个椭圆。
- **跨骨架共享的只有幅度码本 A。** 每个角色有自己的编码器和解码器。**不需要配对数据、不需要关节对应、不需要骨架拓扑。**

**码本大小 vs 重建（厘米）vs 跨物种 manifold 重合度（%）**：

| \|A\| | 8 | 16 | 32 | 64 | 128 | 512 |
|---|---|---|---|---|---|---|
| 狗重建误差 | 1.86 | 1.67 | 1.41 | 1.24 | 1.19 | **0.87** |
| 人重建误差 | 1.29 | 1.26 | 1.19 | 1.13 | 1.08 | **1.01** |
| 人-狗重合度 | 100 | 100 | **100** | 67.8 | 5.42 | **0.00** |

**重建随码本变大单调变好，而他们真正要的那个性质（共享结构）掉到零。** 他们选了 |A|=32，主动放弃重建质量。

**结论直接砸我们脸上：如果你用重建/预测误差给时间分解打分，你必然会得出"没用"的结论——这是设计决定的。**

他们自己解释为什么管用：**成功的关键在于这个浅层 VQ-PAE 的能力有限。**

### 3.6 PHASOR（2026）—— 有人已经在机器人上做了我们那个探针

arXiv 2606.01851。跨身体的相位锚定动作表示，机器人是 **Unitree G1（32 DoF）、H1.2、Booster T1、Berkeley Humanoid Lite**，加 SMPL-H 人体。**12616 条 AMASS 片段约 40.4 小时，用 GMR 重定向，50464 组同步人-机配对。**

架构就是我们那个慢/快拆分：一个**相位 manifold 分支**（FFT 参数化，按身体部位分）+ 一个**独立的非周期姿态分支**，只在解码时用 FiLM 交互。每部位通道数：手臂 3+3，躯干 2，腿 4+4 = **16 通道 → 32 维相位 manifold**，窗口 T=121 @60fps。

结果：人→机器人检索 **R@1 90.3**（MLP 79.9，VQ 37.6）；机器人→机器人 84.8；模仿 MPJPE 1.62 毫米（原始本体感受 1.83）；RL 运动在 MLP/VQ 基线失败的地方成功。

**注意他们的评测轴：检索、迁移、下游 RL —— 不是短时重建。**

他们承认的局限：PHASOR 围绕周期结构建的，对节律性的运动型行为信息量最大，**对瞬态或非周期动作结构就弱**；而且姿态分支还是每个身体一份，非周期的姿态没有跨身体共享。

### 3.7 反面证据：也许根本不需要相位

**Learned Motion Matching**（SIGGRAPH 2020）明确说：运动**不需要相位或其他附加变量**；四足也是**不需要相位信息、不需要专门的门控网络**就能出高质量运动。内存从 995.6 MB 压到 7.1 MB，197 微秒/帧（PFNN 1370，MANN 2440）。**一个很短的原始特征窗口（脚位置/速度 + 未来 20/40/60 帧轨迹 + 步态标签）加检索，就把时序隐式带上了。**

**MaskedMimic**（SIGGRAPH Asia 2024）更值得注意：它把控制重新定义成**掩码动作补全**——一个模型，条件可以是任意子集的关键帧 / 文本 / 物体。**领域在 2024 年对"什么是可复用原语"的回答是"一个掩码条件模型"，不是"相位/风格拆分"。** 这跟我们单帧掩码那套是同一个思路。

### 3.8 PFNN 的一个关键工程发现

**把相位当额外输入喂进去不管用。** 他们量了 ‖δy/δp‖：相位拼在输入上的标准网络约 0.001，PFNN 约 0.05，**差 50 倍**。加了 dropout 以后相位输入被稀释，网络干脆忽略它，改用别的变量推姿态。

**要用相位就得用它去调制权重，不能拼接。** PFNN 是权重生成，DeepPhase 是 8 个专家的门控，PHASOR 是 FiLM。

## 四、跨身体 / 免重定向的生成

### 4.1 AnyTop（SIGGRAPH 2025）—— 和我们最像的东西

arXiv 2502.17327。特拉维夫大学（MDM 那一脉）。

骨架表示是四元组：静止姿态关节位置、关节关系（父子/兄弟/末端标记）、**两两拓扑距离**（树上最短路）、**关节语义名字**。

**名字用冻结的 T5 编码，拼到每个关节的特征上。** 拓扑作为**加性注意力偏置**注入：`a_ij = (q_i·k_j + a_ij^D + a_ij^R) / √F`，其中 a^D 来自最短路距离的学习嵌入，a^R 来自关系类型。**这是 T5 式的相对位置偏置，不是硬邻接掩码。**

每关节 13 维 = 根相对位置 3 + 6D 旋转 6 + 线速度 3 + 二值脚接触 1。骨架-时间交替的两段注意力。

**这几乎逐条对应我们的 tokenizer：关节名文本嵌入、图偏置注意力、每关节 6D 旋转 + 根相对位置。**

数据：Truebones Zoo，70 个骨架（哺乳类、鸟、昆虫、恐龙、鱼、蛇），1219 条动作，147178 帧。**总共约 40 分钟 @60fps，非常小。** "三个样本就能泛化"这句话是数据严重不均衡的直接后果。

数字（Coverage 越高越好，Local/Inter Diversity 越高越好）：

| 模型 | Coverage | Local Div. | Inter Div. | Intra Div. Diff. |
|---|---|---|---|---|
| MDM* | 71.3 ± 31 | 0.168 | 0.139 | 0.177 |
| SinMDM*（每骨架单训） | **89.3 ± 15** | 0.080 | 0.280 | 0.144 |
| AnyTop | 80.5 ± 20 | **0.252** | **0.312** | **0.118** |

诚实读法：**AnyTop 在 Coverage 上输给单骨架专家**，赢在多样性。这不是"一个模型打赢所有专家"，是"一个模型在 70 个骨架上都还行"。

**没见过的骨架只有两个定性演示**（科莫多龙、猫），**没有任何定量指标**。而且两个都是同科内的（从双足里出蜥蜴，从四足里出猫）。没有昆虫→鸟这种跨大类的例子。

它承认的局限：数据增强复杂度 **O(J²)**，限制了关节数能扩多大。没说但真实：只做无条件/骨架条件生成，**没有文生动作控制、没有物理、没有接触保证**。

### 4.2 SATA（2026）—— AnyTop 的直接后继，把关节名升级了

arXiv 2605.27055。"Semantic-Aware Motion Encoding for Topology-Agnostic Character Animation"。

关键升级：**语义标签是 LLM 生成的，不是原始关节名**。他们用 **Gemini 2.5 Pro** 产生功能性的关节描述，再用冻结 T5 编码。这修的是 BVH 关节名很烂的情况（比如 "Bone_017"）。

架构：对称编解码，空间分支双路（GINEConv 消息传递 + 空间 transformer），时间分支 TimeSformer 式。**语义感知特征调制 = 用语义空间上下文对动作特征做 FiLM。** latent 可以是 VAE（连续）或 **RVQ-VAE（离散）**。只有 **8.41M 参数**，64 帧窗口、16 帧重叠。

数据：AT-HumanML3D（80508 条）+ **AT-AniMo4D（30097 条，115 个动物物种）**。是 Truebones Zoo 的约 30 倍。

数字：AT-HumanML3D 上关节位置 1.357 厘米。**跨数据集人→动物 JP = 34.6 厘米，SAME 是约 398 厘米（基本崩了）。** 在这个 latent 上做文生动作：**FID 0.158（RVQ）/ 1.226（VAE），SAME 是 1.628。**

**跨物种零样本重定向也是纯定性的**，他们明说没有定量协议，因为不存在跨物种的配对真值。他们把"建立跨物种定量协议"列为未来工作。

承认的局限：**只做生物关节系统，不做任意机械结构——也就是不做机器人。**

### 4.3 真机器人这边

**分成两半，而且两半没接上。**

*形态条件的控制（RL / 运动这一线）*

- **MetaMorph**（ICLR 2022）：机器人形态就是另一种可以条件化的模态。token = 肢体 + 运动学/动力学属性。后续工作的评价：MetaMorph 依赖显式形态描述符，在人形全身这个场景泛化很差。
- **Body Transformer**（CoRL 2024）：身体是传感器/执行器的图，**掩码注意力**让每个节点只看自己和直接邻居。这是 AnyTop 骨架注意力的机器人版表亲，但是**单机器人内部的归纳偏置，不是跨机器人方法**。
- **URMA / One Policy to Run Them All**：形态无关的编解码器，四足 + 人形 + 六足一个策略，对没见过的平台零样本或少样本。
- **QWM（四足世界模型，2026）**：形态编成一个 **11 维显式向量**（髋偏移、大腿/小腿长度、膝构型、站姿足印、对数质量、躯干质量比、力矩密度），**明说"不需要文本解析 URDF"**。留出的真机 ANYmal-D 和 Go1 跟踪误差在专家的 10% 内。**但 Unitree B2（重约 4 倍）彻底失败**（回报 2.2 对专家 13.6）。作者原话：**它是四足形态族内部一个受分布限制的插值器，不是通用物理引擎。** 这是整个调研里最诚实的局限声明。
- **灵巧手的 canonical URDF**（2602.16712）：**82 个参数**（掌/指半径、连杆长度、手指基座位置、关节轴、限位，加**手指/关节是否存在的二值标记**）。**训练中完全排除的形态上真机零样本 71%**；Shadow 手 62.9%。

*跨人形（多个机器人身体）—— 真正的前沿，2026*

- **XHugWBC**（2602.05791）—— 这里最强的结果，**而且就是我们数据底座那一系**。形态 = 运动学图 + 邻接矩阵，加一个 **32 维、零填充、跨机器人语义对齐的关节空间**。从 G1 模板做物理一致的形态随机化，生成 12 个仿真机器人。**12 个留出仿真机器人零样本：100% 存活，跟踪误差约为专家的 85%。真机 7 个平台零样本：Booster T1、Fourier N1、Unitree G1 变体、AgiBot X2、Dobot Atom、Unitree H1-2，100% 任务成功。**

  **它承认的局限恰好是我们的题目**：它依赖一个统一的**命令**接口，**做不了动作跟踪，因为动作跟踪仍然需要针对具体身体的重定向。跨身体的直接动作模仿仍然是开放问题。** 而且 sim-to-real 的速度跟踪相对差距从 27.45%（G1）到 **107.93%（Dobot Atom）**，大机器人退化严重。

- **VENOM**（2606.16696）：GPT 式全身动作跟踪器，覆盖 **5 个人形**（G1、H1、H1v2、Fourier N1、Booster T1-29DoF），6156 小时训练数据从 RL 专家蒸馏。RMSE 0.1052 弧度。**但：每个身体一套输入嵌入和动作头，不能泛化到没见过的机器人，训练前还是要逐机器人重定向。**
- **Any2Any**（2605.23733）：把预训练的全身跟踪策略迁到新人形，只要约 1% 的算力/数据。运动学对齐 + **LoRA 只进动力学敏感模块**，5.26% 可训参数，约 22.5 GPU 小时。**明说不是零样本。**
- **GMR**（ICRA 2026）：大家实际在用的务实基线。**基于 IK**（mink + MuJoCo），不学习，**17 个人形**，CPU 上 35–70 FPS。任何"免重定向"的主张都得先打赢它，而大部分论文没试。
- **RoboGhost**（2510.14952）："免重定向"讲得最清楚的一个：直接用语言接地的动作 latent 条件化人形策略，跳过显式动作解码和重定向。部署延迟 5.84 秒 vs 带重定向的 17.85 秒。**局限：只有 Unitree G1（23 DoF），每个动作域一套策略，真机结果只有定性的。** 所以这里的"免重定向"是**一个身体内部免管线**，不是免身体。

*操作策略这边*：Open X-Embodiment（22 个本体，100 万+ 轨迹）靠的是**把数据汇到共享动作空间，完全不建模形态**。CrossFormer（20 个本体）**每个本体一个动作头**——所以按构造就服务不了没见过的机器人。

### 4.4 关键空位：文本形态描述符在机器人上没人做

**图形学这边：有，而且是核心招数。**
- AnyTop：BVH 关节名 → 冻结 T5 → 每关节特征。
- SATA：Gemini 生成功能语义标签 → 冻结 T5 → FiLM 调制。
- OmniZoo（140 个物种）：拓扑感知骨架嵌入进入和文本融合的共享 token 空间。

**机器人这边：基本没有。**
- QWM 从 USD 提形态但转成 **11 维数值向量，明确避开文本**。
- 灵巧手论文是 **82 个数值参数 + 二值存在位**。
- XHugWBC 是**手工设计的 32 槽 canonical 映射**，不是学出来的语言嵌入。
- MetaMorph 是数值肢体属性 token。
- 机器人里的 LLM 工作（VLA、π 系列、GR00T N1）用语言描述**任务**，从不描述**形态**。GR00T N1 处理不同状态/动作维度靠的是**每本体的编解码器**——CrossFormer 那套。

**所以"把 URDF 的关节名/连杆语义过一个文本编码器，让动作模型零样本泛化到没见过的机器人"这个想法，在机器人侧目前是没人认领的。** 它在动物骨架上被证明可行（AnyTop、SATA），而且结构上正好是 XHugWBC 明说的那块缺口。

### 4.5 跨身体：解决了的 vs 开放的

**解决了：**
1. 同胚或只差骨长的重定向，**不需要配对数据**——SAN（2020）起，现在是常规货。
2. 基于 IK 的人→人形重定向，实时，约 17 个机器人——GMR。不优雅，能用。
3. 一个 transformer 控制多个**预先指定**的本体，每本体一个头——CrossFormer（20）、VENOM（5）、RT-X（22）。正向迁移是真的。
4. 在紧的形态族内部对未见身体零样本——XHugWBC（12 仿真 / 7 真机，100% 存活）、跨形态起身（86 ± 7%）、灵巧手（真机 71%）。
5. 一个模型生成约 70–140 个动物拓扑的动作——AnyTop、SATA、OmniZoo。

**开放的：**
1. **跨身体的定量评测协议不存在。** 没有跨物种/跨机器人的配对真值，所以 AnyTop 和 SATA 的未见骨架结果都是定性的。**图形学这半边所有零样本数字都是图，不是指标。想要一个能站住的贡献，指标本身就是空地。**
2. **跨身体的动作跟踪/模仿。** XHugWBC 说得很白：通用策略只在统一命令接口下有效，动作跟踪还得逐机器人重定向。**没有人有一个"给一段动作 + 一个新机器人的描述就能跟踪"的模型。**
3. **外推 vs 插值。** QWM 的 B2 失败是标准反例：同厂商，重 4 倍，策略崩。实际上"零样本到未见形态"的意思是"训练形态分布里的未见采样"。
4. **跨拓扑大类的迁移。** 没人展示四足→双足，或人形→非人形机器人。
5. **物理。** 所有拓扑无关的生成工作（AnyTop、SATA、UniMoGen）都是运动学的。机器人那边有物理但没有拓扑通用性。**没有人两样都有。**

## 五、给我们的具体架构建议

每条都挂着证据和我们自己的数字。

### 建议 1：时序层不要做 next-frame，做 next-scale（粗到细）

**证据**：MoScale 的诊断和我们的病一模一样——动作短期高度可预测，模型靠吃这个可预测性降 loss，不学全局时间结构。他们的解法是残差量化分 4 级、序列长度 (6, 12, 24, 49)，从粗到细自回归，HumanML3D FID 0.046 打过 MoMask++ 的 0.072。FAST 从信息论上给了同一个结论：高频下 token 的边际信息趋近于零，模型退化成复制。FAST 的展平顺序**故意**把所有维度的最低频系数排在最前面，就是为了让自回归先出形状再出细节。

**对我们的数字**：我们的 93.9% 复制率和 77.7% 冗余是同一件事的两个测法。**在最粗的尺度上，没有"上一帧"可以复制，退化路径被结构性堵死。** 这比加 dropout、加 scheduled sampling 都根本。

**具体做法**：在现有 FSQ 之上加一层时间金字塔。比如 32 帧的段，尺度设 (2, 4, 8, 16, 32)，每一级只编码上一级没抓住的残差。生成器按尺度自回归，一次出一整级。我们的双流（pos / rot）可以各自建金字塔，或者共享尺度但分流码本。

### 建议 2：token 粒度定在每秒 5–8 个，不要逐帧

**证据**：人体动作侧从 T2M-GPT 到 MoMask 全部收敛到 **1 token = 4 帧 ≈ 200 毫秒 ≈ 每秒 5 个 token**。FAST 侧是**每条手臂每秒约 30 个 token，跟控制频率无关**。ActionCodec 推荐**每 chunk 16 个 token、词表 2048**，并且说 **token 预算比词表大小更决定过拟合**。2606.27547 的消融：K=4096 时只有 24% 的码在用，K=2048 有 76%。

**对我们的数字**：R7 说我们的"词"是 pos 流 290 万种、rot 流 178 万种，**65%/59% 只出现一次**。R7 自己的总结已经点出来了：**词表粒度太细，词几乎不逐字复用。** 这正是逐帧粒度的症状。R8 说 32 帧的本征维度只有 8.7——**一段 32 帧动作大约值 8–9 个独立数，硬塞 32 × 3328 个整数是荒谬的浪费。**

**具体做法**：时间上先降 4 倍。如果沿建议 1 做金字塔，最粗那级就是天然的语义 token，可以直接当 LLM 词表候选。

### 建议 3：分块生成必须用 RTC 式软掩码重叠，不要硬切

**证据**：Physical Intelligence 的 Real-Time Chunking 把 chunk 之间的重叠当成**补洞问题**，用三段式软掩码：已提交的动作 mask=1 冻住，未来 mask=0 自由，中间过渡区**平滑衰减**。每一步去噪时用梯度把当前预测拉向已冻结的部分。结果：高延迟下仍有 94.1% 成功率，**性能随延迟基本不变**，而同步方法线性退化。ActionCodec 独立测到：相邻 chunk **70% 时间重叠 → 500 步内成功率 33.4%**，朴素 VQ-VAE 8.2%，FAST 2%。BEAST 用 B 样条的连续性从表示层面保证 chunk 之间无接缝。

**对我们的数字**：我们的"分块 latent 扩散抖"就是硬切接缝。**这不是模型问题，是采样调度问题，有现成的解。**

**具体做法**：chunk 之间留 50–70% 重叠；软掩码的衰减区放在重叠段中部；在离散 token 上做的话，用 MaskControl 的可微期望采样（DES）让梯度能从解码后的关节位置流回 logits。

### 建议 4：约束继续走"训练时教条件 + 推理时投影"，这条路我们已经领先，把它做成论文的主张

**证据**：CondMDI（SIGGRAPH'24）做过三选一的消融——补洞会跳、引导还是会跳、**训练时把条件教进去才平滑**。ACMDM 把 OmniControl 的误差降 3.4 倍、速度提 32 倍，靠的就是绝对坐标 + 训练时条件 + **去掉推理时引导**。而**硬约束这块整个领域是空的**：MaskControl 自己说 logit 优化不保证精确满足；Kimodo 说轻量后处理可以精确命中，然后**把这步从所有实验里排除了**；**没有任何一篇文生动作论文管关节限位**。

**对我们的数字**：我们的单帧掩码训练 = CondMDI 的做法。我们的 DLS 投影 = 那个所有人都提一句然后跳过的后处理，但我们**做了并且量化了**：微米级、限位违规 0%、比纯 IK 好 2–2.5 倍。**最好的对照数字是 MaskControl 的 0.98 厘米和 KV-Control 的 0.40 厘米——都是软的。我们是硬的。**

**具体做法**：把时序层的约束按 ARDY 的方式注入——**训练时从真值里采样稀疏掩码约束（时间上稀疏 + 关节上稀疏），推理时不用引导**；然后在每个 chunk 解码后跑一次 DLS 投影 + 限位。**要补的实验是量化投影的真实感代价**（投影前后的 FID / 脚滑），因为这是全领域没人做过的测量。

### 建议 5：SE(3) 约束用傅里叶特征做连续条件，不要量化成 token

**证据**：往 LLM 里注入连续值，把数字切成文本 token 会丢失量级的连续感知；**傅里叶特征映射再投影到隐藏维**是现在的推荐做法，FFAT（Fourier Feature Action Tokenizer）就是这么给 VLA 做连续动作条件的。Transfusion 用 21.8% 的算力追平 Chameleon，诊断是**量化本身就是信息瓶颈**——这是"连续模态硬塞进离散词表要付代价"的最强论据。

**对我们的数字**：我们的约束是**微米级精度**的 SE(3) 命令。**把微米级的东西量化成 token 是自相矛盾的。** 输出可以离散（token 给 LLM），输入的约束应该保持连续。

**具体做法**：SE3 约束 = 位置（傅里叶特征）+ 6D 旋转 + 关节 ID（复用现有的 SigLIP 关节名嵌入）+ 时间戳，投影到隐藏维，当成额外的条件 token 或者 FiLM 调制参数。**不要把它编成码本。**

### 建议 6：相位探针要重跑，窗口至少 121 帧 @60fps（或 61 帧 @30fps），并且换评测指标

**证据**：DeepPhase、WalkTheDog、PHASOR **全部**用 T=121 帧 @60fps 约 2 秒的窗口。人的步态周期是 1.0–1.2 秒。**16 帧的 rFFT 频率分辨率是 3.75 Hz，1 Hz 的步态整个落进直流 bin——数学上无法分解。** 而且 WalkTheDog 的表 1 vs 表 2 证明：**重建随码本变大单调改善，而跨物种共享结构掉到零**。他们主动选了差的重建。

**对我们的数字**：我们的 16 帧探针**在配置上就不可能成功**，这个负面结果不能拿来否定时间分解。

**具体做法**：(a) 窗口拉到 ≥61 帧 @30fps；(b) **评测换成检索/对齐，不用重建 MSE**——DeepPhase 的表 4 协议（匹配姿态间的平均关节距离），或者 PHASOR 的跨身体检索 R@1；(c) 相位**不要拼接，要调制**（PFNN 量到拼接的梯度敏感度差 50 倍：0.001 vs 0.05），用 FiLM，PHASOR 就是这么干的；(d) 相位分支**保持浅而且量化**，WalkTheDog 原话是成功的关键在于浅层 VQ-PAE 的能力有限。

**但也要诚实**：即使重跑，走路为主的语料上期望值就该低。DeepPhase 自己的表：**双足走路 +2.8%，芭蕾 +2.8%，而足球 +60%、表现性舞蹈 +71%、单脚跳 +145%**。我们的 R8 读数一致：走路 7.1 维、跳舞 15.4 维。**如果要验证相位，得先有舞蹈/格斗/球类数据。** LAFAN 有打斗和舞蹈（R8 读数 10.6/14.9，明显高于 AMASS），是现成的测试床。

### 建议 7：并进 LLM 词表时，抄 MotionLLM 的保守配方，并盯 logit 漂移

**证据**：MotionLLM 是记录最完整的配方——**加 514 个 token 到 Gemma-2b，文本嵌入和原输出层冻住，LoRA rank 32，只动 1–3% 参数**，效果追平扩散模型。往预训练 LLM 上扩的最大记录是 Being-M0 的 65536（LLaMA2-13B）。Chameleon 的 65536 和 Emu3 的 32768 **都是从零训的，不能当证据**。

**Chameleon 的 logit 漂移必须提前埋监控**：softmax 平移不变，不同熵的模态会打 logit 范数军备竞赛；**训练到 20–30% 才炸，而且稳定和不稳定配置的困惑度看不出差别**。修法：**QK-Norm** 为主，加 **z-loss 1e-5**，大模型再加 norm 重排。

**对我们的数字**：我们的 FSQ 空间是 pos 流 290 万种词、rot 流 178 万种词。**这个规模不可能直接当 LLM 词表。** 必须先按建议 1/2 压到粗尺度，让最粗那级的有效词数落到几千量级。

**具体做法**：分两步走，抄 π₀.₅——**预训练阶段全用离散 token（简单、省算力，π₀-FAST 比扩散 π₀ 少用 5 倍 GPU 小时）；接 LLM 时，加 1024–2048 个 token，冻文本嵌入和原输出头，LoRA。** 保持文本占 token 预算的多数（Chameleon 的文本能力活下来就是因为这个）。另外抄 **knowledge insulation**：掐断动作专家到 LLM 主干的梯度。

### 建议 8：把"URDF 语义 → 文本编码器 → 零样本新机器人"做成明确主张

**证据**：这个想法在图形学上被证明了（AnyTop 用 T5 编码 BVH 关节名，SATA 用 Gemini 生成功能标签再过 T5），**在机器人上没人做**。机器人全在手工设计数值形态向量：QWM 的 11 维（明说避开文本解析 URDF）、灵巧手的 82 参数、XHugWBC 的手工 32 槽 canonical 映射、MetaMorph 的数值肢体属性。而 XHugWBC 承认的局限恰好是这块缺口：**跨身体的直接动作模仿仍然开放，因为动作跟踪还需要逐机器人重定向。**

**对我们的数字**：我们用 SigLIP 关节名嵌入 + 关节轴/限位描述符，从厂商 MJCF 直接建 AgiBot A3/X2 并零样本可用。**这正好是图形学那招在真机器人上的第一次落地。**

**具体做法**：(a) 把这条写成核心主张，对比对象是 XHugWBC 的 32 槽手工映射；(b) 抄 SATA 的升级——**用 LLM 从 URDF/MJCF 生成功能性关节描述**（"右肩俯仰，绕 Y 轴，限位 ±120°"），比原始关节名鲁棒，能救掉命名混乱的厂商文件；(c) 我们的关节轴/限位描述符是图形学没有的东西（动物骨架没有硬限位），这是我们独有的。

### 建议 9：补上跨身体的定量评测协议——这是块空地

**证据**：AnyTop 和 SATA 的未见骨架结果**全是定性的**。SATA 明说不存在跨物种配对真值，把"建立定量协议"列为未来工作。整个图形学侧的零样本证据都是图。

**对我们的数字**：R7 已经有雏形了——**同帧跨身体 cosine 中位数 0.80、不同帧 0.10，ROC AUC = 0.960**；kNN 还能以 71.6% 认出身体（瞎猜 16.7%），**pal_talos 单独占一个岛，认出率 99.9%**。**这套指标（跨身体一致性 AUC + 身体可识别度作为泄漏指标）就是别人缺的协议。**

**具体做法**：把 R7 的 fig2a/fig2b 做成一个正式的 benchmark 定义，加上 PHASOR 的跨身体检索 R@1（人→机器人 90.3、机器人→机器人 84.8，有现成的对照数）。**pal_talos 那个 99.9% 是必须报的负面结果**——它证明协议是有区分度的，不是自己给自己发奖。

### 建议 10：不要迷信重建误差选 tokenizer

**证据**：三条独立线索指向同一件事。ActionCodec：**拓扑稳定性压过绝对保真度**，重建 MSE 是错的选择指标。FASTer：**码本激活是否均衡（归一化熵）比重建误差更能预测泛化**（FAST 有效 2048 只用了 48%，还有一个 token 占 10%）。人体动作侧的双粒度消融：**1/4× 分辨率 MPJPE 更差（30.3 vs 16.6）但生成 FID 更好**。WalkTheDog：**重建随码本变大单调改善，跨物种共享结构掉到零。**

**对我们的数字**：我们的 FSQ 重建是位置 3.3–3.5 厘米、机器人旋转 19.2°、人体旋转 94.5°（twist 主导）。**别再优化这几个数了。** R7 已经量到更有意义的东西：线性探针 82%、跨身体 AUC 0.96、FSQ 7 个常用级全部用满、Zipf 分布跨 5 个数量级。

**具体做法**：tokenizer 的选型指标改成三条——(a) **码本利用率/归一化熵**（我们已经在测：94.5% 的槽位用满 ≥7 级）；(b) **跨身体一致性 AUC**（已有 0.96）；(c) **下游生成 FID**，等生成器有了再测。**重建误差降级成健全性检查，不当优化目标。**

## 六、我们领先在哪，重复造轮子在哪

### 已经领先的

1. **硬约束。** 整个文生动作领域一个硬约束都没有。全是软的。DNO 优化 3–5 分钟到 0，那是收敛不是保证。**我们的 DLS 投影 + 限位强制、微米级、违规 0%，在这个领域是没有对手的。** 最接近的说法是 Kimodo 那句"轻量后处理可以精确命中"，然后他们把这步排除在所有实验之外。
2. **关节限位。** **零篇文生动作论文管这个。** 生成的姿态可以是解剖学上不可能的，没人测。我们不但管，还量化了 0% 违规。真机器人这块是刚需，动画不是。
3. **真机器人的拓扑无关 tokenizer。** AnyTop/SATA 做动物骨架，SATA 明说**不做任意机械结构，也就是不做机器人**。XHugWBC 做真机器人但用手工 32 槽映射，而且**明说做不了动作跟踪**。**"从厂商 MJCF 直接建模型、零样本可用"这件事目前没人做。**
4. **SE(3) 里的旋转。** 全领域只有 Kimodo 报了末端旋转误差（4.18°），其他全是纯位置。我们的表示原生带 6D 全局旋转。
5. **跨身体的定量证据。** 别人的未见骨架结果是图，我们有 AUC 0.96、线性探针 82%、以及诚实的负面结果（talos 99.9% 可识别）。
6. **选 FSQ。** ScaMo（CVPR'25）、MotionMillion、TEXEDO 都独立收敛到 FSQ，理由都是不塌。BEAST 的消融说离散比连续好 12.7%。**我们的选择和 SOTA 一致。**

### 在重复造别人的轮子

1. **关节名文本嵌入 + 图偏置注意力 = AnyTop（SIGGRAPH 2025）。** 逐条对应：他们用冻结 T5 编 BVH 关节名，用最短路距离和关系类型做**加性注意力偏置**，每关节 13 维含 6D 旋转 + 根相对位置。我们用 SigLIP 编关节名 + 图偏置注意力 + 6D 旋转 + 根相对位置。**这个组合不是我们发明的，引用它，然后说清楚我们多了什么**（离散 token、硬约束、关节限位、真机器人）。
2. **SATA（2026）已经把这招升级了**——用 Gemini 生成功能语义标签而不是原始关节名，加 FiLM 调制。**我们可以直接抄这个升级。**
3. **单帧掩码补全 = MaskedMimic（SIGGRAPH Asia 2024）的思路**——把控制重定义成掩码动作补全，条件是任意子集的关键帧/文本/物体。领域 2024 年对"可复用原语"的回答就是这个。
4. **分块的接缝抖动有现成解**（RTC 软掩码重叠），不需要我们自己发明。
5. **AR 复制退化有现成的结构性解**（next-scale AR / MoScale），不需要靠调 dropout。
6. **相位探针的窗口长度是已知常识**（121 帧 @60fps），我们用 16 帧是配置错误，不是发现。
7. **动作本征维度低这件事**，Martinez 2017 的零速度基线和 siMLPe 的 0.14M 参数已经反复说过了。我们的 R8 是更干净的测量（TwoNN 加校准），但结论不新。

### 最该抢的空位

按"好做 × 没人做"排：

1. **硬约束的代价量化。** 全领域没人测过"加投影"对真实感的影响。我们有投影，一个消融就能填这个洞。
2. **跨身体的定量评测协议。** SATA 自己说不存在。我们的 R7 已经有雏形。
3. **快速自回归方法的米制控制误差。** DART、CLoSD、ARDY、COMET 一个都不报。我们如果做出快的时序层并报误差，就是第一个。
4. **URDF 语义 → 文本编码器 → 真机器人零样本。** 图形学证明可行，机器人侧没人认领，XHugWBC 明说这是缺口。
5. **密集轨迹跟踪。** MaskControl 自己的消融：单关键帧 0.10 厘米 → 密集 1.64 厘米，**差 16 倍**。大家都报稀疏的好看数字。我们做机器人，密集才是真需求。
